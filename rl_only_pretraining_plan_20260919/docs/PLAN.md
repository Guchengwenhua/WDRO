# 纯 RL 预训练与扩大训练预算：判断、理论与实验方案

日期：2026-09-19。状态：**方案与既有日志分析完成；本轮没有启动新训练。**

## 1. 结论

**值得做，而且当前最有依据的投入方向是先把基础求解策略训练充分，再做 GroupDRO 或学习型 WDRO 微调。**

这里的预训练，是从随机初始化出发，使用网络自己生成的解及其线长进行强化学习；不需要最优解、GeoSteiner、MST、几何界或传统算法提供的标签。预训练模型可以供后续多个稳健训练分支共享。

判断分为三层：

1. **已有证据**：当前最好的纯 RL 方法训练到结束仍在改善；其训练样本数、初始化和分布覆盖均弱于旧主线。
2. **合理预期**：延长训练、改善基础策略和增加分布覆盖，有机会显著缩小当前差距。
3. **尚不能承诺**：增加多少计算能改善多少、能否追平旧 GroupDRO、学习型对手是否最终更好，都需要新实验。现有结果没有证明存在“去掉 GeoSteiner 必然损失约 16%”的误差下限。

优先顺序：**延长 self-critical 基线 → 四分布纯 RL 预训练 → 同一起点的 Mixed ERM/GroupDRO → 有条件地恢复学习型 WDRO。**

## 2. 这次判断依据什么

### 2.1 当前比较中存在明显的训练预算差异

| 条件 | 当前最强纯 RL 基线 `erm_rollout` | 已有主线 GroupDRO |
|---|---|---|
| 起点 | 随机初始化 | DAC21 预训练 Actor |
| 后续更新 × batch | 2,048 × 64 | 2,000 × 256 |
| sampled 训练样本数 | 131,072 | 512,000，另有预训练历史 |
| 训练数据 | uniform | 每批四分布均衡 |
| 反馈 | 自己生成的解的线长 | 参考归一化 regret |
| 坐标处理 | 固定窗口，不逐 net 缩放 | 逐 net bbox 等比归一化 |

后续 sampled 样本数相差 **3.90625 倍**。这不是总算力倍数：rollout、候选前向、参考计算、预训练都必须另外计费。

统一评测中，纯 RL rollout 的平均线长为 3.596621，旧 GroupDRO 为 3.084174，相差 16.62%；在主线 40,000-net 测试集上分别为 3.770805 和 3.239468，相差 16.40%。这些是**相同测试输入上的模型性能差**，不能解释成 GeoSteiner 的独立贡献。

来源：[统一比较](../../benchmarks/rl_only_vs_mainline_20260919/docs/RESULTS.md)、[训练条件差异](../../benchmarks/rl_only_vs_mainline_20260919/docs/TRAINING_DIFFERENCES.md)。

### 2.2 训练曲线确实支持继续训练

本轮独立读取了 18 份 `progress.jsonl`，核对其与已验收 `complete.json` 绑定的 SHA256，并重算全部选模步数。共 306 条验证记录，核对通过。

下表是**验证集最差组平均线长**，先对每个模型取最差组，再对三个训练种子平均；不是测试集均值：

| 方法 | step 1,536 | step 2,048 | 最后 512 步下降 | 最佳 checkpoint 在终点 |

| self-critical ERM | 4.265968 | 4.096660 | **3.97%** | 3/3 |
| 学习型 WDRO | 4.295181 | 4.166592 | **2.99%** | 3/3 |

self-critical 三个种子最后 512 步分别下降约 7.53%、2.76%、1.15%。因此并非只由一个种子的退化恢复造成平均改善，但改善速度确有明显种子差异。

这支持“当前尚未展示充分训练后的平台期”，不证明后续曲线会保持下降速度。不能线性外推到 8,192 或 16,384 步。

### 2.3 原始 REST 源码还提供了一个可行性线索

检查 `DRO/DRO/REST-main/train.py` 与 `DRO/DRO/WDRO-REST/train.py`，其中 Actor 使用自身采样拓扑的 `eval_batch` 线长训练，Critic 拟合该线长。`algorithms/eval.c::eval` 做的是给定拓扑的长度记账，不调用 `gst_rsmt` 求最优解。

但是旧 `Evaluator` 初始化会加载含 GeoSteiner 的库并调用 `gst_open_geosteiner()`。所以：

- 从目标函数看，原始 REST 代码本身已说明“靠自己动作的线长训练求解器”是合理路径。
- 从依赖隔离看，新预训练仍应使用当前纯 RL 分支的独立长度计算器与禁止外部求解器的检查。
- 这些源码不足以认证历史 DAC21 权重的完整训练谱系。不能直接把旧主线已做过 reference-regret 微调的权重拿来，声称整个训练过程从未使用最优参考。

本方案主线采用可完整追溯的新纯 RL 权重；旧权重继续作为冻结性能参照。

## 3. 理论上，预训练和更多训练能改善什么

### 3.1 不知道最优解，仍然可以得到正确的策略梯度

设输入为 \(X\)，网络采样拓扑 \(a\sim\pi_\theta(\cdot\mid X)\)，环境返回自身动作长度 \(L(X,a)\)。基础目标为

\[
J_P(\theta)=\mathbb E_{X\sim P}\mathbb E_{a\sim\pi_\theta}[L(X,a)].
\]

用不依赖本次采样动作的基线 \(b(X)\)，有

\[
\nabla_\theta J_P
=\mathbb E[(L(X,a)-b(X))\nabla_\theta\log\pi_\theta(a\mid X)].
\]

因为条件于输入及更新前参数，\(\mathbb E_a[b(X)\nabla\log\pi_\theta(a\mid X)]=0\)。基线即使来自当前网络，也应在实现中 `detach`，且在采样动作之前或独立于该动作计算。

因此，最优值不是产生学习信号的必要条件。奖励测量与解的可行性检查仍然需要；它们没有替模型求解另一棵树。

本轮首选当前已经表现较好的 self-critical 更新：

\[
b_\theta(X)=L(X,\operatorname{Greedy}(\pi_\theta,X)),\qquad
\mathcal L_{\rm actor}=\operatorname{mean}[\operatorname{stopgrad}(L-b_\theta)\log\pi_\theta(a\mid X)].
\]

这里 greedy 是**学习得到的网络的解码方式**，不是外加的几何启发式。RL rollout 基线在其他组合优化任务已有先例，但该文献不能替代本项目的验证：[Kool 等，Attention, Learn to Solve Routing Problems!](https://arxiv.org/abs/1803.08475)。

### 3.2 预训练为何可能有效，又为何不能只靠改名

从随机网络出发，首先要学会如何生成较短的可行拓扑；同时加入最坏组权重或动态学习对手，会使输入和梯度目标一起变化。先训练基础策略，再引入稳健目标，可能减少后续优化的不稳定性。

预训练的作用是改变初始化和学习顺序，并为多个后续任务复用成本。**如果数据、目标、优化器状态和更新顺序完全相同，把前一半训练叫作预训练，不会凭空产生收益。**

所以需要同时回答：

- 更多总训练是否有用？比较同一个方法的 2,048、4,096、8,192 步。
- 多分布是否有用？比较相同初始化、相同总预算下的 uniform 与 balanced mixed。
- 先学习平均性能，再学习最坏组，是否比直接 GroupDRO 更有效？比较相同总预算的训练顺序。

### 3.3 不能保证误差单调下降，也不能抹平目标差异

若仅把 Critic 换成更好的动作无关基线，理想策略梯度目标不变；主要影响有限预算下的梯度噪声和训练稳定性。但此前从 reference-regret 改为原始线长，还改变了目标：

\[
J_{\rm regret}=\mathbb E_X[J_X(\theta)/L^*(X)-1],\qquad
J_{\rm raw}=\mathbb E_X[J_X(\theta)].
\]

前者给不同输入乘上 \(1/L^*(X)\) 的权重。对单个输入、无限制策略，两者都偏好更短的解；对共享参数、有限容量的网络，不同输入之间的取舍可能不同。GroupDRO 下这个区别还会影响哪些组被认为最坏。

更多训练主要有机会降低优化不足和采样噪声的影响；不能自动消除模型表达能力限制、分布外泛化问题、训练目标差异或原有长度记账与物理布线长度的差别。非凸策略优化也没有保证每次增加更新都更好。

## 4. 推荐的基础预训练方案

### 4.1 固定不变的部分

- degree 30，沿用当前 Actor 架构与解码可行性约束。
- 仍以自身 REST span 记账线长为反馈，采用独立长度计算器。
- 固定坐标窗口 `[0.1,0.9]`，首轮不同时引入逐 net bbox 缩放。
- sampled 训练 batch 64，greedy 前向 batch 64，保留一致的尾批处理。
- 基础训练使用 self-critical，Adam `lr=1e-4`、梯度范数裁剪 1。
- 首轮沿用三个种子 101、102、103；同种子各比较臂使用可核对的相同随机初始权重。
- 保存 RNG、优化器、BatchNorm 状态、数据流哈希、所有真实前向次数及恢复重放开销。

首轮保留 batch 64 是为了单独判断训练长度效应。现有网络含 BatchNorm，改变物理 batch 或改成梯度累积并不是严格等价操作；“把 batch 改成 256”应另做消融。

### 4.2 多分布纯 RL 预训练

定义

\[
P_{\rm mix}=\tfrac14(P_{\rm uniform}+P_{\rm mix\_gauss}+P_{\rm edge\_bias}+P_{\rm grid\_cluster}).
\]

每批每组 16 个输入，总计 64；全部使用上面的 self-critical 更新，训练到 **8,192 步，即 524,288 条 sampled 训练轨迹**。另有同数量的 greedy baseline 评分。

这在 sampled 数量上接近旧主线的后续 512,000 个样本，但尚不能称为与“旧主线预训练 + 后续训练”总预算相当。

训练和新验证/测试的 `mix_gauss` 为每个 net 独立抽取簇布局，不再让整个验证或测试 split 共用一套中心。其余参数沿用既有四组定义；输入采样与任何求解器无关。训练、验证和测试使用互斥种子命名空间。

首轮不把更大网络、多尺度 degree、PPO、蒸馏、坐标归一化和复杂课程同时叠加。确认基础预算和数据覆盖有效后，再逐项扩展。

## 5. 预训练后如何比较 Mixed ERM 和 GroupDRO

### 5.1 相同起点的微调

每个 seed 使用 mixed 预训练的**固定 step 8,192** checkpoint，包括相同 Actor、BatchNorm 和 Adam 状态。固定起点便于完整核算前置成本，避免给不同微调方法挑不同父模型。

分成两个优先分支，各训练 **4,096 步 × 64**，将学习率统一调整为 `5e-5`：

1. **Mixed ERM**：继续四组均衡等权训练，是“只增加后续训练”的对照。
2. **RL-only GroupDRO**：仍每组 16 个输入，但用在线学习的组权重优化最坏组的自身线长。

两者都使用同一种 self-critical baseline，避免把 baseline 差异混入 GroupDRO 效果。

### 5.2 不依赖参考的 GroupDRO 更新

定义 \(R_g(\theta)=\mathbb E_{X\sim P_g,a\sim\pi_\theta}L(X,a)\)，目标为

\[
\min_\theta\max_{q\in\Delta_4}\sum_g q_gR_g(\theta).
\]

初始 \(q_g=1/4\)。第 \(t\) 步先用历史权重 \(q_t\) 更新 Actor：

\[
\widehat{\nabla J_t}=\sum_gq_{t,g}\frac1{16}\sum_{i\in g}(L_i-b_i)\nabla\log\pi_\theta(a_i\mid X_i).
\]

然后使用这一步、Actor 更新前采集的组平均自身线长 \(\widehat R_{t,g}\)，更新下一步的权重：

\[
q_{t+1,g}=\frac{q_{t,g}\exp(\eta\widehat R_{t,g})}{\sum_hq_{t,h}\exp(\eta\widehat R_{t,h})},\qquad\eta=0.01.
\]

实现使用 log-space。**不能把由本批采样动作决定的 \(q_{t+1}\) 直接套回同一批策略梯度，再无条件声称它是固定组权重下的无偏估计。** 用旧权重更新 Actor，再更新下一步权重，可避免这一额外相关性。

组损失使用真实的自身动作线长，不能用 advantage 均值代替风险；否则一个拟合很好的 baseline 会把组损失抵消掉。也不把 Critic 预测当成最优长度做除法。

代价是原始线长会混入各组固有难度：当前 `edge_bias` 本来就可能更长。必须报告每组变化、组权重和权重熵，判断是否只是把训练集中到了某一组。GroupDRO 文献也提醒最坏训练损失下降不等于最坏测试性能变好，因此保留验证选模：[Sagawa 等，Distributionally Robust Neural Networks for Group Shifts](https://arxiv.org/abs/1911.08731)。

## 6. 学习型 WDRO 和多轨迹学习放在什么位置

### 6.1 学习型 WDRO 暂列第二优先级

已有 WDRO-RL 尚未稳定优于 self-critical ERM，且每步更贵。先让基础求解器充分训练，再判断是否值得重新引入对手。

若增加此分支，同样从 mixed 预训练 step 8,192 开始，4,096 步；固定 `K=8`、`rho=0.04`、既有按 pin 索引对应的运输成本，并把求解器 baseline 统一为 self-critical。提案网络只从当前学习策略自己的线长得到反馈。

本分支的 nominal 中心分布明确改为 `P_mix`，因此与旧 uniform-centered WDRO 是不同的训练问题；不得混称原配置的续跑。学习型候选提案和有限候选选择仍是近似，greedy 候选评分与 sampled Actor 风险也存在差别，不能声称获得精确 Wasserstein 最坏风险。

保留相同真实评分预算的随机提案作为机制对照；它只承担诊断作用，不作为满足“纯学习对手”要求的交付主方法。首轮不扩大 K 或 rho。

### 6.2 平台期后再测试纯 RL 多轨迹基线

可对同一个 \(X\) 独立采样 \(M\) 条拓扑，用其余轨迹构成 leave-one-out baseline：

\[
b_i(X)=\frac1{M-1}\sum_{j\ne i}L(X,a_j),\qquad
\widehat g=\frac1M\sum_i(L(X,a_i)-b_i(X))\nabla\log\pi_\theta(a_i\mid X).
\]

条件于输入和共享的固定编码表示，其他轨迹独立于第 \(i\) 条动作，故这个估计不需要外部参考；也不需要用 greedy 解作训练基线。取 `M=4` 作后续候选，不在本轮基础方案中同时引入。

它可能改善训练信号，但不保证比 rollout baseline 方差更低。必须按总 sampled 轨迹和真实时间对齐预算：64 个输入各采 4 次是 256 条轨迹，不是原 batch64 的等成本替代。固定 64 条轨迹时，4 次采样只能覆盖 16 个独立输入，也有数据多样性代价。

多轨迹和对称性思想可参考 [POMO 原论文](https://arxiv.org/abs/2010.16011)；本式是本方案明确采用的 leave-one-out 估计，不能直接套用 POMO 在 TSP 上的收益数字到 REST。

## 7. 最小、可区分原因的实验安排

### 第一轮：先回答“更多训练”和“更多分布”

| 臂 | 起点 | 训练数据/方法 | 总更新 | 总 sampled 轨迹/模型 | 新增任务 |
|---|---|---|---:|---:|---:|
| A0 | 已验收结果 | uniform self-critical | 2,048 | 131,072 | 0 |
| A1 | A0 的 latest，完整恢复 | uniform self-critical | 8,192 | 524,288 | 3 个续跑，各新增 6,144 步 |
| B1 | 与 A0 匹配的随机权重 | balanced mixed self-critical | 8,192 | 524,288 | 3 个从头训练 |

- A1 保持原学习率、优化器、uniform 数据流和动作 RNG 推进规则。续跑应新建独立分支，显式记录父 checkpoint；不能修改原冻结 protocol 冒充原实验继续执行。
- B1 按每个种子的原始初始 Actor 哈希检查初始化一致；新的未使用辅助网络不能改变 Actor 随机初始化。
- 记录 2,048/4,096/8,192 的固定预算端点。新验证从 2,048 开始每 512 步一次，A1/B1 使用相同数量的选模机会。
- A0 原模型也在新验证和新最终测试中重新推理；不能把旧验证数值直接并进新多布局验证曲线。
- 固定预算端点用于展示训练量变化；最终交付另外报告统一验证规则选出的 checkpoint。

优先执行这 6 个任务，不一开始把全部旧方法再训练一遍。

### 第二轮：比较预训练后如何分配后续算力

| 臂 | 前 8,192 步 | 后 4,096 步 | 总 sampled 轨迹/模型 | 种子数 |
|---|---|---|---:|---:|
| C1 | B1 mixed 预训练 | Mixed ERM | 786,432 | 3 |
| C2 | 同一个 B1 父模型 | RL-only GroupDRO | 786,432 | 3 |
| C3，条件扩展 | 同一个 B1 父模型 | RL-only WDRO，K8 | 786,432，另计候选/对手成本 | 3 |

C1/C2 是优先比较。若 C2 改善最坏组却显著损伤均值，保留 C1 为主模型，不因方法名称更复杂而选 C2。

### 验证“预训练本身有效”的必要额外对照

若要明确声称“先预训练再 GroupDRO 比直接 GroupDRO 好”，增加 D1：**从相同随机权重起步，直接 GroupDRO 训练 12,288 步**。其数据、self-critical、batch、前 8,192 步 `1e-4`/后 4,096 步 `5e-5` 的学习率阶段与 C2 对齐。

C2 与 D1 总 sampled 轨迹和前向预算相同，区别是前 8,192 步的目标及其产生的状态。C2 优于 D1 才能支持学习顺序的收益；C2 仅优于 2,048 步随机起点模型，不能单独证明预训练优于相同成本的直接训练。

预训练成本列两种账：单个最终模型承担完整前置训练；研究总成本中共享父模型只实际计一次。不能把共享预训练成本从单模型效率比较中完全删除。

### 何时再扩大到 16,384 步

先固定 8,192 步作为主比较预算。只用验证集决定后续探索：若 4,096→8,192 的四组平均线长仍下降至少 0.5%，且最差组未恶化，则考虑延长。

如果要比较 A/B 的高预算结果，两臂都延到 16,384；不把一个方法的 16,384 步与另一个的 8,192 步冒充同预算。高预算扩展单独标记为验证集指导的探索，并在新增最终测试前冻结配置。

## 8. 评价、成功标准与停止规则

### 8.1 数据与选模

- 新建独立验证集：每组 2,048 个 net，共 8,192；`mix_gauss` 每 net 独立布局。
- 新建并提前封存最终测试集：每组 4,096 个 net，共 16,384。旧测试已多次被分析，继续作为兼容性报告，不能再称为未见确认集。
- checkpoint 主准则沿用最差组平均自身线长最低、并列取最早。C1/C2/C3 另要求验证四组均值相对共同父模型恶化不超过 1%；父模型作为零步回退候选，各臂同规则。
- 开发和预算选择只读取验证数据。最终测试待模型/比较清单冻结后统一一次评测；评测实际前向与所有失败重试都计费。

### 8.2 报告内容

每组及四组等权平均线长、P95、最差组、三个种子各自结果、训练曲线、greedy 单次推理耗时、真实训练前向/反向数、墙钟时间与有效 worker 时长。

固定候选窗口攻击作为次指标继续保留，所有模型使用相同攻击坐标和评分预算；它仍不是严格 rho 球内鲁棒性证书。主指标坚持单次 greedy，增加测试时采样次数应独立列为推理成本实验。

同训练体系比较使用匹配种子与匹配 net；与旧 DAC21 体系比较时种子独立重采样、net 配对。新独立布局数据可按 net 重采样；若实现改为共享布局，则必须按布局分块，不能把同布局的 net 都当独立样本。先报告三种子的探索性区间，最终关键结论建议补至五种子；预先定义主要比较并处理多重检验。

### 8.3 什么算有用的结果

- **增加训练有效**：A1 在相同新测试上优于 A0；报告改善大小、种子一致性和置信区间。
- **数据覆盖有效**：相同 8,192 步的 B1 优于 A1，尤其体现在非 uniform 组。
- **稳健微调有效**：C2 比 C1 改善最差组，且均值符合预设退化容忍；不能只看某个种子的最好值。
- **预训练顺序有效**：相同总预算下 C2 优于 D1。
- **工程目标**：旧兼容性测试上先争取将与 GroupDRO 的现有差距缩小一半。对应 RL test 均值约 3.340398、主线 test 约 3.505137。这是待验证目标，不是预测，也不是相对最优解误差。新测试应重新计算参照值。

若训练损失继续降低而新验证不改善，应优先检查数据覆盖、采样/greedy 差异、BatchNorm、探索程度和目标权重，而不是继续机械翻倍算力。若 raw GroupDRO 权重长期集中在单组，先解释其平均性能取舍，再考虑另立目标消融。

## 9. 计算量、时间与服务器执行方式

### 9.1 历史速度只用来估量级

已完成 self-critical 三种子的训练更新均时为 **0.874、1.060、1.370 秒/步**；这是当时共享 GPU 环境下的观测，不是当前独占 GPU 速度。

| 任务 | 新增更新总数 | 按历史速度估计，含约 10%–30% 非训练余量 |
|---|---:|---:|
| A1：3 个续跑到 8,192 | 18,432 | 约 5–9 worker 小时 |
| B1：3 个 mixed 从头预训练 | 24,576 | 约 7–12 worker 小时 |
| C1+C2：两个分支 × 3 seeds | 24,576 | 约 7–12 worker 小时 |
| 可选 D1：直接 GroupDRO 总预算对照 | 36,864 | 约 10–18 worker 小时 |

A1+B1+C1+C2 核心方案约 **18–34 worker 小时**。各行做过取整，合计区间按未取整数计算。worker 小时是各训练进程耗时之和，不是专属 GPU 利用率积分，也不等于实际等待时间。GroupDRO 复用本批长度，新增组权重计算预计很小，但实现后仍需测量。新验证更大、服务器负载变化都会影响估算。

WDRO-RL 旧实验约 2.76–4.69 秒/步；新 self-critical 版本还要 baseline 前向，不能直接套用旧速度承诺完成时间。

### 9.2 如进入执行，先测量再挂后台

1. 核对当前 GPU 显存、利用率、现有任务、CPU 与磁盘，完成新分支的 CPU 检查和 GPU smoke。
2. 每种方法用短 pilot 测真实吞吐、显存峰值与恢复行为；pilot 成本单列。
3. 优先并行独立种子/实验臂，按稳定吞吐和足够余量准入。显存有空余不代表计算资源空闲；不以填满显存作为性能目标。
4. 使用可恢复队列、tmux、心跳、进程起始标识和文件锁；中断从完整 checkpoint 恢复，原结果保持冻结。
5. 所有新代码、日志、数据、临时文件和缓存都放在 `DRO/Codex` 内。只使用可安全利用的资源，不终止或挤占他人的任务。
6. 队列稳定后，根据实测每步时间、剩余步骤、并发数和排队状况给出当次完成时间范围，再交接后台运行。

## 10. 本轮产物与建议

本目录新增的是分析报告、可重复运行的日志提取脚本及证据表/曲线；没有新增训练权重，没有启动待监控的 GPU 任务。

建议首先实施 **A1 + B1 的六个任务**，回答训练不足和分布覆盖这两个最直接的问题。之后用同一个纯 RL 预训练起点比较 C1/C2。若需要发表“预训练优于相同成本的直接训练”的结论，再补 D1；学习型 WDRO 和多轨迹方案在基础求解器足够强后单独评估。

这条路线既保留“学习反馈完全来自强化学习内部”的要求，也能逐步区分性能收益究竟来自更多更新、更多分布，还是后续稳健训练方法。

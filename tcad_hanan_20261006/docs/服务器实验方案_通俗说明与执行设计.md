# Hanan 论文服务器实验方案

日期：2026-10-06。状态：方案与数据准备，尚未启动正式科研实验。

## 1. 先把要做的事情说清楚

用户此前在笔记本上完成了理论推导、例子和原型工作。这里将它们作为研究基础，不当作本轮服务器正式实验结果。运行在 CPU 上的路由比较、统计和求解器实验也都是科研实验，并不需要使用 GPU 才算实验。

我们的输入是一张芯片中需要互相连接的一组端点，其中一个端点是信号源。算法要画出横平竖直的一棵树。我们关心两件事：所有实际导线加起来有多长，以及从源走到最远端点要走多远。共享导线只算一次，交叉处接通，最后必须得到树。

Hanan 网格，就是过原始端点画出的横线和竖线。原方法只在这些线的位置布线；我们的办法允许再增加少量横线或竖线，给算法更多选择。新增线只是允许放导线的位置，并不是必须铺满的线，也不是新增必须连接的端点。

因此先回答四个问题：

1. 只用原网格，是否真的会漏掉更好的解？
2. 在真实芯片上，增加少量线是否有用？
3. 能否提前判断哪些网不需要补线、哪些网确实有损失？
4. 改善要花多少时间和内存，快速算法是否划算？

训练新策略是第五项扩展，在共同求树后端准备好之后再进行。

### 源点和坐标规则

- 主实验保留唯一驱动端能明确恢复的普通信号网。LEF 的单元 pin 方向与顶层端口方向按各自语义解释，不能把网列表第一项自动当作驱动端。
- CircuitOps 中的 `dir` 等字段需结合已下载的导出源码解释。旧 parser 主要面向无根线长，不能直接承担源路径实验。
- 多驱动、无法确定驱动端、缺失端口坐标、异常坐标的网记录原因；不随意删掉几个端点后当作完整原网。
- 几何上重合的端点合并，但保留原 pin 与源的映射。分组中的 n 是合并后的不同端点数，包含源。
- ISPD 2008 若不能恢复实际源，另设“指定源几何轨道”：按原始文件出现顺序取第一个不同坐标作为主源；在预先抽取的子集上换到距离端点质心最近和最远的端点，观察源选择影响。同一比较使用相同源，不宣称它是真实驱动端。
- 保留原始 DBU 或精确有理坐标。若需归一化，两轴使用同一个比例，保存逆变换。不能分别拉伸 x、y 后声称仍在评价原始几何。
- 本论文评估二维、无障碍、无层的物理树。真实芯片的障碍、层信息保留在原始文件中，本轮指标不等于详细布线合法性或真实电气延迟。

## 3. 实验一：原网格到底漏掉了什么

**通俗问题：如果端点不变，只允许走线的位置更多，是否真的能画出一棵更好的树？**

先用论文五点例子和一般位置扰动例子展示几何差异，再在选定真实小网上做有上下界的比较。比较原网格、加入少量线的网格以及连续坐标候选，源点、目标和时间预算相同。

五点例子在长度和最远路径各占一半时，解析目标值从 4 到 3.75，下降 6.25%。这是论文给出的数学参照，不是这次服务器已测得的结果。正式实验记录实际程序画出的树能达到多少。

输出是每个网的三张树或对应树文件，以及总线长、最远源路径和综合分数。对能认证的网给出最优值或上下界；未解出的网报告剩余差距与用时。

默认昂贵认证总预算为每个网每个权重 60 秒，其中每次 LP 至多 10 秒并受剩余总时间约束。论文解析例子可给 300 秒总预算。内存预算建议 8 GiB/任务。预算包括建模、候选生成、物理恢复和本次科研认证需要的证书计算；不能把“每次 LP 限时”当成整个任务限时。

固定一种拓扑求出的最优值只代表该拓扑。只有全局下界与真实可行树闭合，才记录为全局求解。严格 Hanan 缺口要求连续候选比所有 Hanan 解的可靠下界还低。

## 4. 实验二：补线在真实芯片上有没有用

**通俗问题：给同一个算法更多走线位置，最终能省多少线，或者缩短多少最远路径？**

第一阶段完全可以使用固定的 CPU 求树算法。先实现同一个后端的三种模式：

| 名称 | 唯一变化 | 回答什么 |
|---|---|---|
| 原网格 | 只允许原端点的横纵坐标 | 原始参考 |
| 理论补线 | 加入论文规则产生的坐标 | 我们的补线能带来多少改善 |
| 等数量均匀补线 | 横线、竖线分别加入同样多条，但均匀分布 | 改善是否只是因为可选位置变多 |

三者使用同一求树算法、同一初始树、相同搜索参数和相同随机种子。新增坐标必须真正被后端允许使用，不能只写入配置。均匀线与原坐标重合时按预先固定的规则补足相同数量，不看测试效果决定位置。

后端尚待实现或选择，本方案不宣称已有一个可直接接入 PatLabor 的增广求树器。只把现有树移动一下属于后处理对比，须与允许重新搜索拓扑的主对比分开。

综合分数沿用论文：F=(1−λ)×总线长+λ×最远源路径，越小越好。λ 越大越重视最远路径，同时始终分别报告两个原始指标。

- 主权重：0、1/3、0.4、0.5、2/3、0.8、0.9、0.95、1。
- 主精度参数：ε=0.2、0.1、0.05、0.02。ε 是理论允许误差参数；实际加了多少不同横线和竖线另行记录。
- 一套比较固定搜索调用数，建议默认 64 次候选评价；每次调用含义必须对所有方法一致。
- 另一套比较相同端到端时间，建议 0.1、1、10 秒/网的预算曲线。所有方法固定一个 CPU worker，计入坐标构造、求树和物理恢复。超时仍保留已有合法候选，报告未完成状态。
- 固定调用数也需要相同外层时间保护，例如 60 秒/网；超时保留在分母中。
- 原始补线输出与“原网格候选和补线候选取最好”分别报告。联合候选的全部成本计入总预算，不能免费多跑一次原方法。

得到的结果应能直接回答：“每个设计平均改善多少，多少网改善、持平或退化；多花多少时间；相同总时间下是否仍有改善”。改进率为 (原方法分数−新方法分数)/原方法分数；负数照常保留。

PatLabor 的原实现作为单独的外部参考。若无法取得完整实现和参数，就记录为未完成参考，不用自写近似版本冒充忠实复现。SALT 可作为补充工程基线，不增加无关模型训练。

## 5. 实验三：能否提前判断哪些网值得补线

**通俗问题：能不能先花很少时间看看这个网，避免对所有网都做昂贵搜索？**

全体网先计算原坐标间距、分层长度下界以及论文的无损条件。然后在预定小网子集运行更强下界与连续候选。

每个网、每个权重只进入三类之一：

1. 有数学依据说明原网格已经足够；另标是否找到了具体最优树。
2. 找到一棵原网格外的树，并证明它好于所有原网格树。
3. 目前判断不了，包括时间不够、下界不够强、数值证据不能认证等。

“目前判断不了”是正常结果，不归入第二类，也不归入第一类。

依次统计廉价条件、对偶下界、单分量移动候选、补线候选分别新增多少可判断的网，增加多少耗时。权重 λ≤1/3 或 λ=1 的理论无损情况单列，不能让这些容易情形掩盖中间权重的困难。

严格证书所需的有理或区间计算属于这项科研实验的核心测量；本方案不附加通用软件测试、smoke 测试、全量回归或独立工程验收平台。未取得可靠证书时，只报告数值上下界和“未解决”。

## 6. 实验四：补多少线合适，快速转换是否真省时间

**通俗问题：补线太少可能没效果，太多又可能太慢，怎样找到有用的取舍？**

这组实验画两类图：

- 新增线数—解的质量：比较四档 ε，对五点解析前沿另外加入 ε=0.01、0.005、0.002。除不同权重外，也问“最远路径最多只能这么长时，最少需要多少导线”。这样才能看到中间的折中方案。
- 总运行时间—改善幅度：看返回核加速后，整体是否真的更快，而不是某个内部步骤更快。

“前沿”就是一组无法同时再缩短线长和最远路径的折中方案。小例子用已知数学前沿作参照；大网使用各方法共同产生的可行解集合，称为参考前沿。画线连接两个点不代表中间点一定是可行树。

快速转换使用同一棵输入树和同一组允许坐标，对比直接事件算法与返回核算法。除总时间外，记录准备坐标、消去零返回分量、事件处理、交叉接通/重合合并/恢复树所花的时间，以及内存、返回分量数、交点数。

CPU 工程上的重点是 q 很小和 q 接近树规模时各表现如何，以及交点恢复会不会成为瓶颈。计时子集预先固定，每个方法重复 3 次记录中位数和波动；重复用于性能实验，不把它们当成三个独立芯片样本。普通正式质量评估不反复重跑确定性算法。

旧返回核实现只在长度斜率大于零时反向，而现稿要求零斜率时也采用反向规则。正式实现需先同步当前算法规则，再将同一输出树的线长、逐路径变化、2L+p 变化作为科研测量字段。代码整理不附加未请求的工程检查。

## 7. 可选第五项：重新学习选点策略

**通俗问题：允许更多走线位置后，原来学会的选点习惯是否需要调整？**

在固定算法/固定策略的补线对比完成后，再做原策略×原网格、原策略×补线网格、新策略×原网格、新策略×补线网格的四格对照。

PatLabor 的选点策略是四参数评分，不应自动扩成另一套大型神经网络项目。其策略训练和主要路由成本可主要在 CPU 上；只有采用实际需要 GPU 的模型实现时才使用 GPU。

若正式开展训练，至少 5 个预先指定种子，例如 11、23、37、53、71；训练数据、总预算、验证选择规则保持一致，训练成本与推理成本分别报告。配置必须记录每个种子的训练样本数、迭代数和总资源上限，未补齐这些字段时不启动训练。调参只使用验证设计。

即使前面的补线收益不明显，也保留结果。是否保留训练主张属于论文范围选择，不能通过选择性报告让结果看起来更好。

## 8. 在服务器上怎样执行

前四组以 CPU 为主。建议初始并行 8 个网任务，每个求解器 1 个线程，防止多进程与内部线程相乘。运行前读取当时 CPU/内存负载、磁盘空间和 GPU 状态；本轮读到的资源情况不当作未来预约。

将工作目录、临时目录和缓存设在本专题下。大输出继续使用附加盘，并在专题内建立入口，禁止修改或删除其他项目已有数据。原始输入副本不作为实验输出覆盖。

CPU 长任务也建议使用 tmux；GPU 长任务按 SKILL.md 必须使用 tmux。每个已完成网原子写入结果，保存完成清单、配置和种子。恢复时跳过已提交结果，中断中的网从头计算，最多损失该网的资源预算。训练另保存模型、优化器、调度器、精度缩放器、步数、随机状态与采样位置，不能仅依赖 tmux。

GPU 的型号、卡号、Batch Size、数值精度和实际预算写入配置；只占用当时适合的资源，不终止其他任务。吞吐和预计剩余时间由正式实验日志估计，不额外安排用于调参的 smoke 试跑，不编造 ETA。

长任务正常启动后，交接只说明任务名、tmux、日志、输出、进度和有依据的 ETA，不持续占用对话轮询。

## 9. 如何报告结果

每个设计先汇总，再给设计等权平均和网等权平均。两者分开，避免大设计主导全部结果。不同源点轨道和不同数据套件分别统计。

配对比较使用同一批网，报告原始差值和相对改善。必要时按设计家族聚类做置信区间；设计家族太少时直接列出逐设计结果，不用海量相关网制造虚假的显著性。预先固定的多个权重和 ε 全部保留，不仅报告最好的一格。

结果报告只回答：实际产生了哪些数据，这些数据支持什么结论。记录失败与超时及其影响。不写泛化的“验证充分”“系统可靠”等评价，不把理论常数写成测量结果，也不把数据复制完成写成实验完成。

论文图表建议为：数据与源点清单；原网格/理论补线/均匀补线的质量与时间表；三类判断比例与各证书阶段耗时表；新增线数—覆盖误差图；总时间—收益图。训练开展后再添加四格对照。

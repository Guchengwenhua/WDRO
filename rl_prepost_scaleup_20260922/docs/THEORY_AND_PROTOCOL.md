## 2. 三种预算分别解决什么问题

记 W 为 REST 基础预训练 updates，A 为冻结 REST 上的攻击器预训练 updates，T 为之后共同训练 updates。

* 增加 W：改善基础布线策略及 value/Adam 状态，为各后训练方法提供更充分训练的相同起点。
* 增加 T：考察相同初始化、目标、数据流、物理 batch 下的持续优化效果。
* 增加 A：只在同一固定 REST 上延长攻击器学习，检验搜索 gain 是否继续提高；这不自动意味着路由器会更好。

REST 自身策略目标为 J(θ)=E_X E_{Y∼πθ}[C(X,Y)]。使用动作无关 value baseline，有

    ∇J = E[(C(X,Y)−V(X)) ∇logπθ(Y|X)].

不调用最优解、GeoSteiner、MST、Hungarian 或外部预训练模型。继承旧轮已经记录谱系的纯 RL checkpoint，不把旧 checkpoint 当成免费训练。
增加 updates 可能降低优化不足，但非凸更新、过拟合、策略饱和或目标不匹配均可能使额外训练无收益甚至退化。
保持 batch=64、网络、Adam 学习率、奖励与数据分布不变；不同时换 baseline、扩大网络、换归一化或混入 OOD 训练。

## 3. 攻击目标及方法保持一致

qθ(Z) 是 REST 自己生成的 greedy 拓扑线长，c(X,Z)=(1/n)Σ_i||x_i−z_i||_1，F=qθ(Z)−λc(X,Z)。原中心包含在 K=8 个真实评分中。
Best-of-K PPO 使用 M−M_{−j} 的替换优势；条件独立提案下 M_{−j} 与动作 j 无关。PPO clipping 是近似更新，不继承无偏或单调改善保证。
Sequential PPO 使用当前位移、前步反馈和历史最佳反馈；r_t=M_t−M_{t−1}，γ=1，因此 Σr_t=max_j F_j−F_0。继续从当前点提案，按所有已真实评分候选择优。
每坐标相对原中心 ε=.08，窗口 [.1,.9]，最小 L1 pin 间距 1e-6；非法候选回退并照常计费。
coev 保持 λ←max(0,λ+10(mean c−.04))，续训携带已有 λ，新的后训练分支从 λ=5 开始。
greedy 搜索和 sampled REST 更新是交替近似；有限候选及对偶递推不是连续 Wasserstein 鲁棒性认证。
理论背景：[PPO](https://arxiv.org/abs/1707.06347)、[Wasserstein DRO 对偶](https://arxiv.org/abs/1604.02199)。

## 4. 主实验：分开增加 W 和 T

所有设置保持 degree30、8 seeds=301–308、batch64、K8。主矩阵中攻击器预训练 A 固定为 2048，分别在各自的 frozen REST 上训练。

| 基础预训练 W | 后训练 T=2048 | 后训练 T=8192 |
|---|---|---|
| 2048 | 已有 checkpoint，在全新测试集重评 | 从同一 checkpoint 连续训练至 8192 |
| 8192 | 新长预训练模型后训练至 2048 | 同一条轨迹继续至 8192 |

每格包括 ERM、Random、Best-of-K PPO、Sequential PPO；不按旧轮暂时排名删除 PPO 或 Random。ES/REINFORCE 的旧轮完整结果仍保留，主扩展聚焦这四个方法以控制总成本。
另固定保存/评价 T=4096，用于训练长度曲线，不据此选模。
比较 T 时保持相同起点；比较 W 时后训练步数相同。W 的干预包含基础 Actor、value 和 Adam 状态的训练历史，以及在该基础 Actor 上相同步数 A 的攻击器适配，不能解释为只改变 Actor 权重。
W=2048,T=8192 与 W=8192,T=2048 均有 10240 个 REST sampled updates，可比较训练预算分配；二者对抗评分数不同，不是等总 FLOPs 比较。

## 5. 单独扩大 A，避免与主矩阵混淆

对旧轮每个 seed 的固定模型 Best-of-K / Sequential checkpoint，从 A=2048 连续训练到 A=8192；REST 始终是该 seed 原有 W=2048 的冻结模型。
统一评价 A=2048、4096、8192，λ=1/5/10，Random/ES 同预算对照。主诊断为 λ=5 的 gain 改变，另报成本、no-move、KL、clip fraction、最终 σ。
这批 A=8192 攻击器不接入主 coev 矩阵，避免把 W、A、T 三项变化揉在一起。若其搜索改善得到证据，之后才需要新增 A 的路由器训练因果比较。

## 7. 评价与统计

每个预定 checkpoint 使用相同的新四分布测试中心：常规每分布4096，独立攻击每分布512、Random32/ES32、λ=0；fixed 每分布512。保留逐 net 原始数组和候选。
评价前后保存/恢复训练 RNG，保证插入 checkpoint 评价不改变后续训练轨迹。step4096只作预定曲线点，不做早停或最佳点选择。

主指标 R 为 Random32 和 ES32 两类独立攻击下的四分布等权平均线长，越小越好。预注册六个有方向比较：

1. 两种 PPO 各自 W=2048 时，T=8192 相对 T=2048 的改善。
2. 两种 PPO 各自 T=8192 时，W=8192 相对 W=2048 的改善。
3. W=8192,T=8192 时，两种 PPO 各自相对同配置 Random 的改善。

先按相同 seed 和中心配对，再对8个seed均值差做单侧符号翻转检验（完整枚举256种符号），六项一起做 Holm FWER .05。
正向seed至少6/8、Holm p≤.05、相对改善至少.5%方可标记SUPPORTED。符号翻转依赖零假设下差值符号可交换/对称；8 seeds 的总体外推仍有限。
分别报告两个独立攻击指标，避免平均值掩盖某一攻击退化。预期收益不达标或为负也保留。R下降不能单独称为所有分布或攻击都改善。
nominal、分布分项、P95、worst group、T=4096、A扩展、等REST更新预算分配均为次要结果；给2000次crossed seed/common-center bootstrap描述区间，不把未校正区间称为主结论。
每个完整 coev 轨迹报告末64/256步平均cost−ρ、全程新增片段平均cost、超额比例和λ；续训的这些均值不能冒充从step1起的全历史均值。

## 8. 调度、恢复与交付

旧轮的源文件、参数和队列不修改。新tmux先完成有界GPU工程试跑与独立数值审计；正式队列须等旧轮全部训练退出且终态验收为COMPLETE后，接棒使用最多8张GPU。

保持每卡一个新正式worker、每worker单线程BLAS/PyTorch；最终独立数据重建/审计用最多8个CPU进程。预计新增占用低于20GiB，保留至少25GiB磁盘。

旧源任务未完成则等待，不重复启动或读取正在写入的checkpoint。新队列保存心跳、命令、PID/start_ticks/boot ID、锁、重试和源绑定。

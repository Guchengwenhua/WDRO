# 纯 RL 训练规模与预训练顺序：冻结实验方案

日期：2026-09-21。此文在新 GPU 实验之前编写。范围：degree 30、三个训练种子的受控探索实验。新文件与数据均在本目录的父目录内，旧实验保持只读。

## 1. 要回答的命题

旧 RL-only self-critical 只有 2,048×64=131,072 条 sampled 训练轨迹。已验收日志中最后 512 步的验证最差组均值仍改善约 3.97%，三个种子的最佳模型均在终点。这支持继续实验，不能证明欠训练是全部原因。

本次区分四种解释：(H1) 基础优化预算不足；(H2) uniform 数据覆盖不足；(H3) 后训练预算不足；(H4) 学习平均风险后再学最坏组的顺序有收益。架构、坐标处理、batch、初始化、动作随机流、解码与指标固定。不同目标的数据权重仍可能导致不可由更多训练消除的差异。

## 2. 不用最优解的学习依据

输入 X，策略采样可行拓扑 a∼πθ(·|X)，环境仅返回该动作长度 L(X,a)。训练目标 J=E_X E_a L(X,a)。对于在动作采样前计算、与该动作无关的 b(X)，有

∇θJ = E[(L(X,a)−b(X))∇θ log πθ(a|X)]，因为 E_a[∇logπθ]=0。

使用当前学习网络的 greedy 自解作为 b，评估模式、无梯度，训练 loss 为 mean(stopgrad(L−b) logπ)。采样前设置逐步动作随机种子；保留原 BatchNorm 训练模式与更新。无 GeoSteiner、MST、HPWL 界、FLUTE、Hungarian、最优标签或外部预训练。可行性检查及自身拓扑线长记账是环境，不替网络构造解。确定性的网络解码不属于外部确定性求解器。

这里采用 REST 的 span 线长语义；共线坐标时可能重复计算物理重叠线段，因此不得将其冒充精确布线并集长度或相对最优 regret。原始线长与参考归一化 regret 是不同的跨样本加权目标。

Rollout 策略梯度的研究先例：[Kool 等，ICLR 2019](https://arxiv.org/abs/1803.08475)。这里沿用项目自身当前策略基线，不声称完全复刻论文的基线更新协议。

## 3. GroupDRO 与训练顺序

四组 g 为 uniform / mix_gauss / edge_bias / grid_cluster。R_g=E[L|g]，目标 minθ max_{q∈Δ4} Σ_g q_g R_g。每批每组 16 个，总 batch 64。

本步用历史 q_t 做 Actor 梯度：Σ_g q_t,g mean_{i∈g}[(L_i−b_i)∇logπ_i]；随后用该批更新前采样长度的组均值更新 log q_{t+1}=log q_t+0.01 R̂_t，再减 logsumexp。不得将由本批动作计算的下一步权重回用于本批梯度；不得以 advantage 均值代替组风险。

保存全部 q、熵及组风险；原始长度可能使权重偏向固有线长较大的组。验证最坏组改善不能替代未见测试。理论动机参见 [Sagawa 等，ICLR 2020](https://arxiv.org/abs/1911.08731)，本实验不能继承其其他任务上的数值收益或收敛保证。

## 4. 实验矩阵与预算

种子 101/102/103，各比较相同种子的随机 Actor 哈希必须与旧实验一致。预训练保存 Actor、BatchNorm、Adam 和随机状态。所有路线在全局 step≤8,192 用 lr=1e-4，此后统一 lr=5e-5；Adam，梯度裁剪 1，batch 64。将训练阶段改名本身不产生收益。

|标识|前置训练|本任务目标/范围|最终全局更新|每模型累计 sampled 轨迹|
|---|---|---|---:|---:|
|U|旧 uniform self-critical 2,048 完整状态|uniform ERM，2,049→8,192|8,192|524,288|
|M|匹配随机初始化|四分布等权 ERM，1→8,192|8,192|524,288|
|D|匹配随机初始化|四分布 GroupDRO，1→12,288|12,288|786,432|
|ME|M 的固定 8,192 状态|四分布 ERM，8,193→12,288|12,288|786,432|
|MG|同一个 M 的 8,192 状态|四分布 GroupDRO，8,193→12,288|12,288|786,432|
|SG|M 的固定 2,048 状态|四分布 GroupDRO，2,049→12,288|12,288|786,432|

共 18 个训练任务，实际新增 135,168 次 batch 更新（8,650,752 sampled 轨迹，另有等量 rollout 评分），共享 M 的前置训练只实际执行一次。单模型效率需完整计入前置成本。每次验证和最终评估另计前向数量与用时。

保存 2,048/4,096/6,144/8,192/10,240/12,288 中适用的固定端点，另外保存统一验证选出的 best。U 从旧 2,048 状态继续，保留旧 uniform 逐步数据和动作 RNG 公式；旧 checkpoint 拷贝到新目录并核验已验收 SHA256。M/D/SG/ME/MG 在每个相同全局 step 使用一致的四分布输入与动作种子，避免按分支重新开始随机数据流。

SG 的 6,144 与 MG 的 12,288 都有 4,096 步后训练，但总预算和后训练学习率不同，只作组合方案的描述性对比，不能独立归因于预训练长度；MG/SG/D 的 12,288 对比才是相同总预算、相同全局学习率计划的阶段分配实验。SG 的 6,144→12,288 可检验延长后训练（包含预设全局学习率阶段）。ME/MG 同起点同预算隔离稳健目标。本轮扩大的是更新次数和新采样轨迹总量，不是固定有限训练集上的 epoch 次数。

先完成固定实验矩阵，本次不根据最终测试临时追加超参/预算。16,384 及更多种子属于之后的新协议。本轮不重新训练学习型 WDRO 对手，也不读取旧主线预训练权重；不能由本轮结果宣称 WDRO 对手更强、已经追平旧 DAC21 主线或已在真实芯片上验证。

## 5. 数据与测试隔离

固定 [0.1,0.9] 窗口，不逐 net bbox 归一化；沿用旧四组参数。mix_gauss 改为每个 net 独立簇布局，以避免整套测试共用少数中心；所有方法用同一新布局定义。训练/验证/测试独立命名空间。验证每组 2,048，总 8,192；新测试每组 4,096，总 16,384。数据准备仅生成坐标和哈希，不推理测试。准备时核验 train probes/val/test 及组间没有重复 net。

训练进程审计钩子禁止打开 test 文件。全部训练任务结束、模型哈希与选模清单冻结后，评估任务才获准读取新测试。三个训练种子的净表均值、P95 和最坏组保留；所有最终推理为 greedy、物理 microbatch64、固定 padding。旧已查看测试仅作为兼容性分析，不能用于新确认结论。

每 512 步验证，从 2,048 起；U/M 在 2,048→8,192 具有相同选模机会。固定端点是规模效应主分析，防止训练越久选模机会越多的偏差。ME/MG/SG 将共同父模型作为零步回退候选，验证等权均值不得较各自父模型恶化超过 1%，以最差组最小、并列取最早选模。D 则按完整训练阶段选择。不同起点的 best 只作交付模型比较，不代替固定预算检验。

## 6. 预注册统计与结论判据

主要比较固定为五项：U8192 vs U2048 的等权均值；M8192 vs U8192 的等权均值；MG12288 vs ME12288 的最坏组；MG12288 vs D12288 的最坏组；MG12288 vs SG12288 的最坏组。补充 SG12288 vs SG6144 描述后训练规模，不进入主要显著性结论。

报告 baseline−candidate 的改善，正数为更好；相对比例的分母为 baseline。按种子配对，再按组内同一 net 配对的双层 bootstrap，5,000 次；分别报告 95% 区间及五项 Bonferroni 同时区间（每项 99%，全族名义95%）。三个种子只能给探索性不确定性，有限种子 bootstrap 不能证实普遍性；不得将几万条 net 当作几万个独立训练种子。

支持某一主要命题需要：平均相对改善至少 0.5%，至少 2/3 种子改善，校正区间下界>0。稳健微调另要求等权平均线长恶化≤1%。否则分别标记趋势、不支持或不确定，不把未显著等同于无效。若 U8192 明显优于 U2048，可说训练不足是旧结果的一个原因；不能说是唯一原因。平台期只说明本预算范围，不能证明已达到模型上限。

最终报告还须列训练曲线、各组/P95、组权重、每模型完整轨迹/前向成本、实际墙钟/worker 时间、失败重放次数、峰值显存、数据/模型/源码 SHA256。完成标记需要所有18训练和对应测试任务齐全、线长独立重算、账本及退出锁核查。

## 7. GPU执行和无人值守

最多 8 个 worker，每卡一个、每 worker 3 CPU 线程（当前亲和范围31 CPU）。连续三次采样 GPU 利用率≤35%、可用显存≥8 GiB 才接入；进程分配器最多约6 GiB，保留显存余量。运行中只暂停自己的 worker：显存余量<2 GiB、磁盘<20 GiB、非有限值或损坏哈希触发保护。不得中断或修改其他用户进程，不预分配无用显存。

每 128 步原子保存 latest，关键端点完整保存；验证 best 与日志偏移绑定，恢复时验证哈希，保留实际调用账本中的重放。每进程 flock、PID/start_ticks/boot_id，tmux 持久调度，依赖自动串接，失败有限重试，最终统计自动生成。资源等待时间无法预先承诺；ETA 以正式 batch64 短跑实测速率加验证开销估计，并随 heartbeat 更新。

预计总产物<6 GiB，正式开始前核验磁盘。诊断单元测试、GPU短跑和中断恢复通过仅代表工程启动门槛，不算科学验收。

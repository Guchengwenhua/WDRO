# DRO/Codex 中强化学习对抗样本搜索方法与流程

核对日期：2026-09-21。本文依据当前平级方法目录中的实际源码、冻结协议和已有验收文档编写，重点回答：**攻击器看到了什么、如何改变坐标、如何得到奖励、如何更新，以及生成的样本怎样进入 REST 训练。**

这里的“对抗样本”是一组新的 pin 坐标。攻击器希望在允许的几何变化内，找到让当前 REST 布线模型表现更差的输入。它输出坐标，REST 在这些坐标上重新生成树，然后用实际生成树的线长等指标评价攻击效果。

## 2. 先区分三个角色和三种“好坏”

### 2.1 REST、攻击器、价值网络各自做什么

用不同符号避免都叫 Actor 或 Critic 带来的混淆：

| 对象 | 符号 | 输入 → 输出 | 学习目的 |
|---|---|---|---|
| REST 布线策略 | \(\pi_\theta\) | pin 坐标 → 离散树结构 | 找到更短的树 |
| 坐标攻击策略 | \(p_\omega\) | 原坐标、价格，或搜索状态 → 连续位移 | 找到让 REST 得分更差的输入 |
| REST baseline | \(V_{\rm rest}\) | 坐标 → 预计布线成本 | 降低 REST 策略梯度的方差 |
| 攻击器状态价值 | \(V_\nu\) | 攻击状态 → 预计攻击回报 | 为 PPO / MAPPO 提供 baseline |
| 攻击器动作价值 | \(Q_\nu\) | 状态和位移 → 预计攻击收益 | 为 MADDPG bandit 提供动作方向 |
| 几何搜索 surrogate | \(C_\phi\) | 候选坐标 → 预计真实评分 | 用于另一些 Critic 梯度搜索路线 |

尤其要注意：**PPO 的价值网络、MADDPG 的 Q、REST 的 baseline 和 Critic 梯度搜索代理，不是同一个用途。**

### 2.2 统一记号

设一个 net 有 \(n\) 个 pin：

\[
X=(x_1,\ldots,x_n)\in\mathbb R^{n\times2}
\]

是原坐标；\(Z\) 是合法化后的候选坐标；\(a\) 是攻击器采样的原始连续动作。记：

\[
Z=T_X(a),\qquad
L_\theta^g(Z)=\ell\bigl(Z,\operatorname{REST}_{\theta,\mathrm{greedy}}(Z)\bigr).
\]

这里 \(T_X\) 表示裁剪、坐标窗口约束、必要的归一化和非法点处理。不同分支的 \(T_X\) 并不完全相同。

攻击器在固定 \(\theta,\lambda\) 下最大化：

\[
F_{\theta,\lambda}(X,Z)
=q_\theta^g(Z)-\lambda c(X,Z).
\]

- \(q_\theta^g\)：当前分支规定的 REST 真实坏度，越大表示越差。
- \(c(X,Z)\)：运输代价，衡量输入改变了多少。
- \(\lambda\ge0\)：运输价格，越大越不鼓励大幅移动。
- 原中心满足 \(c(X,X)=0\)，因此 \(F(X,X)=q_\theta^g(X)\)。

最终在已评分的候选集合中选择：

\[
Z^*=\arg\max_{Z\in\{X,Z_1,\ldots,Z_{K-1}\}}F(X,Z).
\]

这些实现把原中心排在第一个，`argmax` 遇到并列取最早项，所以原中心与其他候选并列最优时保留原中心。最终分数至少不低于本次已评分的原中心；这只是有限候选集合内的性质。

### 2.3 同一个 F，在不同分支中含义不同

| 分支 | \(q_\theta^g(Z)\) | \(c(X,Z)\) | 指标解释 |
|---|---|---|---|
| v3.1 | \(L_\theta^g(Z)/L^*(Z)-1\) | Hungarian 最小匹配平均 L1 | 使用精确参考的相对 regret |
| Oracle-free | \(L_\theta^g(Z)/B(Z)-1\) | Hungarian 最小匹配平均 L1 | 几何下界归一化指标 |
| RL-only / RL research | \(L_\theta^g(Z)\) | 同索引 pin 的平均 L1 | REST 自身生成树的原始线长 |

Oracle-free 中：

\[
B(Z)=\max\{\operatorname{HPWL}(Z),\operatorname{MST}_{L1}(Z)/2\}.
\]

代码采用 \(B\le L^*\) 的几何下界关系。因此 \(L/B-1\) 是较保守的下界归一化坏度，不能把它直接称为真实 relative regret。

两种运输代价分别是：

\[
c_{\rm match}(X,Z)=\frac1n\min_{\sigma\in S_n}
\sum_{i=1}^n\|x_i-z_{\sigma(i)}\|_1,
\qquad
c_{\rm index}(X,Z)=\frac1n\sum_{i=1}^n\|x_i-z_i\|_1.
\]

前者会寻找最便宜的 pin 配对，后者直接保留 pin 的对应关系。因此，即使两个分支都写 `lambda=1` 或 `K=8`，也不能据此认定它们在优化同一个问题。

源码依据：[v3.1 真实评分](/remote-home/Guilin/DRO/Codex/adversarial_v3_1_20260912/adv_v3/common.py:148)、[Oracle-free 下界与匹配](/remote-home/Guilin/DRO/Codex/oracle_free_20260915/geometry.py:124)、[RL research 代价](/remote-home/Guilin/DRO/Codex/rl_research_20260915/policies.py:42)。

### 2.4 搜索评分与 REST 更新采用不同模式

搜索时 REST 使用 greedy 模式，目的是给候选提供固定规则下的反馈。共同训练时，REST 在选中的 \(Z^*\) 上重新采样树，用采样树的真实成本做 REINFORCE 更新。

因此需要区分：

1. **攻击分数更高**：当前固定 REST 在某些候选上的表现更差。
2. **REST 训练损失下降**：布线策略正在适应训练输入。
3. **独立测试更好**：训练后的 REST 在新输入或独立攻击下线长更低。

第一项是搜索能力，第三项才是最终模型收益；两者需要分开验证。

## 3. 所有 RL 攻击器共用的基本流程

~~~mermaid
flowchart TD
    A[原始坐标 X 与当前价格 lambda] --> B[攻击策略生成连续动作]
    B --> C[位移裁剪与坐标合法化]
    C --> D[REST 在新坐标上重新生成 greedy 树]
    D --> E[计算真实坏度与运输代价]
    E --> F[得到 F 和训练用回报]
    F --> G[从原中心和所有已评分候选中选 Z*]
    F --> H[训练阶段更新攻击策略和所需价值网络]
    G --> I{当前任务}
    I --> J[固定模型评价：记录搜索结果]
    I --> K[共同训练：REST 在 Z* 上采样树并更新]
    K --> L[根据选中样本的平均成本更新 lambda]
~~~

图中对序贯方法的“生成动作 → 评分”会重复多次；普通单步方法则可以一次生成多个彼此条件独立的完整候选。

### 3.1 一次动作通常移动整组 pin

单步攻击器的动作形状为 \(n\times2\)。对于 degree30，它一次产生 60 个连续分量。所谓“一步”是一次生成整组位移，不是只动一个 pin，也不是让 REST 只执行一步布线动作。

### 3.2 RL 不需要对真实布线评分求坐标梯度

REINFORCE 和 PPO 使用动作的对数概率更新策略。真实奖励可以通过离散树生成、线长计算和合法化获得，而不需要对这些过程求导。

这里必须保存**裁剪前高斯动作**的 log probability。若 \(a\sim p_\omega\)，实际执行 \(T_X(a)\)，正确的评分函数梯度基于：

\[
\mathbb E\left[F(X,T_X(a))\nabla_\omega\log p_\omega(a\mid s)\right].
\]

裁剪后的坐标可能堆积在边界，不能直接当成未经裁剪的高斯样本来算密度。v3.1、RL-only 和 RL research 都在原始动作上计算概率，在合法化后坐标上计算奖励。

### 3.3 两类合法化不要混用

| 分支 | 几何处理 | `.08` 的含义 |
|---|---|---|
| v3.1 | 裁剪到窗口后重新归一化 bbox；必要时修复或回退 | 提案位移的限幅；后续归一化可能再次改变最终坐标 |
| Oracle-free | 裁剪到窗口后重新归一化；非法则回退 | 同样是归一化前的提案限幅 |
| RL-only / RL research | 固定 `[.1,.9]²`，不做逐 net bbox 重缩放；间距违规则回退原中心 | 合法化后仍保持相对原中心的逐坐标位移不超过 `.08` |

RL research 的序贯方法另外限制**每一步动作**在 `±.04`；累积位移仍相对原中心限制在 `±.08`。最大逐坐标位移 \(\epsilon\) 与平均运输预算 \(\rho\) 是两个不同约束，不能互相替代。

依据：[v3.1 legalize](/remote-home/Guilin/DRO/Codex/adversarial_v3_1_20260912/adv_v3/common.py:90)、[Oracle-free legalize](/remote-home/Guilin/DRO/Codex/oracle_free_20260915/geometry.py:113)、[RL research legalize](/remote-home/Guilin/DRO/Codex/rl_research_20260915/policies.py:49)。

## 4. v3.1：单步 REINFORCE，先学提案，再用于 RL4 / RL64

代码入口：[rl.py](/remote-home/Guilin/DRO/Codex/adversarial_v3_1_20260912/adv_v3/rl.py:45)、[search.py](/remote-home/Guilin/DRO/Codex/adversarial_v3_1_20260912/adv_v3/search.py:18)、[joint.py](/remote-home/Guilin/DRO/Codex/adversarial_v3_1_20260912/adv_v3/joint.py:531)。

### 4.1 输入、动作与网络

策略观察原始坐标 \(X\) 和运输价格 \(\lambda\)。每个 pin 将 `(x, y, lambda)` 编码，再拼接全体 pin 的 mean/max pooling，输出该 pin 两个坐标方向的高斯均值。网络另学习两个方向的共享标准差。

策略只提议坐标位移，不预测最优树，也不直接输出攻击分数。初始均值为零、标准差为 `.02`；采样动作被限幅到 `±.08` 后送入 v3.1 合法化。

### 4.2 固定 REST 时如何训练攻击器

每次训练更新按以下顺序进行：

1. 生成一批新的 uniform 原中心 \(X\)。
2. 每个中心只采样一个高斯动作，得到一个合法候选 \(Z\)。
3. 用冻结 REST 分别评价 \(X\) 和 \(Z\)，同时取得相应的参考长度。
4. 计算候选奖励 \(F(X,Z)\)。
5. 用原中心的实际分数作为 baseline：\(b(X)=F(X,X)\)。
6. 计算优势 \(A=F(X,Z)-F(X,X)\)。
7. 最小化攻击器损失：

\[
\mathcal L_{\rm attack}=-\frac1B\sum_{b=1}^{B}
\operatorname{stopgrad}(A_b)\log p_\omega(a_b\mid X_b,\lambda).
\]

这里的 \(B\) 是 batch size，和第 2 节的几何下界 \(B(Z)\) 不同。正优势会提高这类动作的概率，负优势会降低这类动作的概率。实现没有奖励标准化、熵奖励或 surrogate 奖励。

默认固定训练为 `256 updates × batch64`，学习率 `3e-4`；每 32 步在 128 个固定验证中心上评价，并保留验证候选平均 F 最好的攻击策略。每个训练中心需要原中心与候选共两次真实评分；验证也消耗独立评分预算。

### 4.3 学好后如何搜索

~~~text
给定原中心 X、价格 lambda、已训练攻击策略：
    RL4：采样 3 组完整位移
    RL64：采样 63 组完整位移
    对每个提案做合法化
    把原中心 X 放在候选集合第一项
    对全部 4 / 64 项计算真实 F
    返回 F 最大的候选
~~~

`propose()` 还按坐标规范排序来分配随机噪声，再恢复原 pin 顺序，以保证固定种子的候选集合不因输入 pin 的重排而任意变化。

**RL4 / RL64 是实际评分预算，不是 4 步 / 64 步反馈轨迹。** 这些候选都从原中心独立提议，后一个候选不读取前一个候选的评分。

### 4.4 `rl_frozen4` 与 `rl_joint4`

两个继续训练分支都先加载已学好的攻击器，每次给 REST 选择一个 RL4 候选：

- `rl_frozen4`：后续只训练 REST、REST baseline 和价格；攻击策略参数固定。价格仍会作为策略输入，因此“固定参数”不等于每次输出相同。
- `rl_joint4`：除上述更新外，每 4 次 REST 更新额外训练一次攻击器。使用新的一批中心、刚更新后的 REST 和当前价格，重新评价原中心及一个新提案。

这个额外 REINFORCE 更新每中心增加两次评分，应单独记账。它不是免费复用 RL4 的全部旧候选，也不是在一条 4 步搜索轨迹中即时更新策略。继续训练的默认预算为 512 次 REST 更新。

固定攻击实验与继续训练均有完成记录，但已有报告没有建立低预算 RL 或在线交替训练的稳定优势。见 [v3.1 最终状态](/remote-home/Guilin/DRO/Codex/adversarial_v3_1_20260912/docs/FINAL_STATUS.md)。

## 5. Oracle-free：以几何下界为反馈的单步 REINFORCE

代码入口：[ProposalPolicy](/remote-home/Guilin/DRO/Codex/oracle_free_20260915/search.py:33)、[wdro_rl 搜索](/remote-home/Guilin/DRO/Codex/oracle_free_20260915/search.py:139)、[训练调用](/remote-home/Guilin/DRO/Codex/oracle_free_20260915/train.py:311)。

### 5.1 它改变了什么

这个分支不使用 GeoSteiner 精确最优标签。它用实际 REST 线长和 \(B(Z)=\max(\mathrm{HPWL},\mathrm{MST}/2)\) 得到 \(q_B(Z)\)，再减去 Hungarian 运输惩罚。

提案网络由逐 pin 编码器、全局 mean/max pooling 和位移头组成。高斯均值通过 `epsilon * tanh` 限制，标准差为所有 pin 和两个方向共享的可学习标量。**策略输入只有坐标 X，不包含 λ**；价格会影响奖励，但网络没有显式价格条件。

### 5.2 一次搜索和更新

1. 为每个 \(X\) 独立采样 7 个完整位移动作。
2. 对动作限幅、合法化，与原中心组成 8 个候选。
3. 逐候选重新生成 REST greedy 树，计算实际线长、下界与 \(q_B\)。
4. 计算每个提案的奖励 \(r_j=q_B(Z_j)-\lambda c_{\rm match}(X,Z_j)\)。
5. 对第 \(j\) 个提案，用其他 6 个提案的平均奖励作 baseline：

\[
b_{-j}=\frac16\sum_{\substack{l=1\\l\ne j}}^{7}r_l,
\qquad A_j=r_j-b_{-j}.
\]

6. 用 \(-\operatorname{mean}_{b,j}[\operatorname{stopgrad}(A_{bj})\log p_\omega(a_{bj}\mid X_b)]\) 更新提案网络。
7. 从原中心与 7 个候选中按真实 F 选 \(Z^*\)。
8. REST 在 \(Z^*\) 上采样树，以对应的下界归一化成本更新自己；最后根据选中成本更新 λ。

与 v3.1 相比，这里的 baseline 是其他提案均值，攻击器直接嵌入外层交替训练；并没有先固定 REST 独立预训练 256 步的阶段。

### 5.3 状态与解释

[冻结协议](/remote-home/Guilin/DRO/Codex/oracle_free_20260915/protocol.json)规定 degree30、batch64、K8、2048 步；这是配置，不代表全部执行完成。[当前状态记录](/remote-home/Guilin/DRO/Codex/oracle_free_20260915/docs/STATUS.md)明确该分支已暂停，后续转入 RL-only，未完成科学验收。

其名称中的 Oracle-free 是去掉精确最优参考，不表示去掉 MST、几何下界或匹配算法；这些内容仍存在于奖励与运输代价中。

## 6. RL-only：以自身线长为奖励的单步 REINFORCE

代码入口：[search.py](/remote-home/Guilin/DRO/Codex/rl_only_20260915/search.py:33)、[外层 update](/remote-home/Guilin/DRO/Codex/rl_only_20260915/train.py:309)、[protocol.json](/remote-home/Guilin/DRO/Codex/rl_only_20260915/protocol.json)。

### 6.1 环境与奖励

该分支将反馈简化为：

\[
F(X,Z)=L_\theta^g(Z)-\lambda c_{\rm index}(X,Z).
\]

REST 和攻击器均从本分支随机初始化开始，不载入外部预训练权重。环境为固定 `[.1,.9]²`，不做逐 net bbox 重缩放；没有精确最优解、MST、几何下界或 Hungarian 匹配。

### 6.2 攻击器生成样本的流程

网络与上一节的 `ProposalPolicy` 结构相同，也不显式输入 λ：

~~~text
X → 逐 pin 特征 + 全局 mean/max 特征
  → 高斯均值与共享标准差
  → 7 个独立整网位移动作
  → 位移限幅 + 固定窗口裁剪 + 间距检查
  → 原中心加 7 个候选
  → REST greedy 自身线长及 indexwise 运输代价
  → 真实 F 最大的 Z*
~~~

攻击器训练仍使用其他提案的 leave-one-out 平均奖励 baseline；7 个提案中每一个都参加 REINFORCE 更新，最终只有一个候选进入本轮 REST 更新。因此，“最终选最大值”并不意味着攻击器已经在直接优化 best-of-K 目标，第 10 节才专门改变了这一点。

### 6.3 外层一轮的实际顺序

1. 生成当前 uniform 中心 batch。
2. 用当前 REST 和 λ 给 8 个候选评分并选 \(Z^*\)。
3. 用这批候选的真实 greedy 线长拟合辅助 surrogate。
4. 用保存的 `proposal_loss` 更新 RL 提案策略。
5. REST 在已选 \(Z^*\) 上采样树，计算自己的 sampled 线长。
6. 用 REST baseline 形成成本优势，更新 REST 和 baseline。
7. 根据选中样本的平均运输代价更新 λ。

第 3 步是这份训练器共用的辅助网络更新；`wdro_rl` 的候选选择和策略奖励依赖真实线长，不使用 surrogate 的预测值作为替代。

默认 degree30、seeds101/102/103、batch64、K8、2048 步，\(\rho=.04\)、\(\lambda_0=1\)、价格学习率 10。每 128 步进行四分布验证，以最差分布平均自身线长选模。

该分支的 [复验状态](/remote-home/Guilin/DRO/Codex/rl_only_20260915/docs/STATUS.md)表明 18 个正式模型已完成，但 WDRO-RL 相对 Random 的稳定优势尚未建立。自身线长的改善也不能直接换算为最优误差的改善。

## 7. 六方向研究共用的网络、状态和实验阶段

接下来的方法都位于 [rl_research_20260915](/remote-home/Guilin/DRO/Codex/rl_research_20260915/README.md)，主要实现集中在 [policies.py](/remote-home/Guilin/DRO/Codex/rl_research_20260915/policies.py:125)。它们沿用 RL-only 的固定窗口、实际自身线长和 indexed mean-L1 运输。

### 7.1 统一状态表示

对于第 i 个 pin，网络输入 8 个特征：

\[
o_i=\left[
x_{i,x}-.5,\ x_{i,y}-.5,\quad
d_{i,x}/\epsilon,\ d_{i,y}/\epsilon,\quad
\frac{\lambda}{1+\lambda},\ \tau,\quad
F_{\rm current}-F_0,\ F_{\rm best}-F_0
\right].
\]

其中 \(d_i\) 是当前坐标相对原中心的位移，\(\tau\) 是已经用掉的移动步数比例，\(F_0=F(X,X)\)。

- 单步方法的位移和三个搜索上下文量均为零；只有原中心和价格条件随输入改变。
- 序贯方法的位移、已用步数、当前增益与历史最佳增益会在每步评分后更新。
- 状态中包含历史最佳**分数**，没有包含历史最佳候选的完整坐标。

逐 pin 共享编码器输出局部特征，拼接全局 mean/max pooling 后产生位移均值。所有方法都能利用全局 pin 摘要，所以 MAPPO 的特点不能仅归结为“看到了其他 pin”。

`PinActor` 输出：

\[
\mu_i=\epsilon\tanh\bigl(h_\omega(o_i,\operatorname{pool}(o))\bigr),
\qquad a_i\sim\mathcal N(\mu_i,\operatorname{diag}(\sigma^2)).
\]

共同默认值为 width64、初始 `sigma=.04`、`epsilon=.08`，两个坐标方向分别有共享的标准差参数。对数标准差在前向时被限制，使标准差位于 `[.002,.2]`。它是探索尺度，实际执行动作仍要限幅。

源码依据：[特征构造与 PinActor](/remote-home/Guilin/DRO/Codex/rl_research_20260915/policies.py:79)、[CentralValue](/remote-home/Guilin/DRO/Codex/rl_research_20260915/policies.py:109)。

### 7.2 三个实验阶段

| 阶段 | 更新对象 | 作用 | 冻结协议 |
|---|---|---|---|
| warmup | REST 与 REST baseline | 产生同 seed 的共同布线起点 | 从随机初始化做 256 次 ERM 更新 |
| fixed | 攻击器及所需 value / Q | 独立测量学习搜索的能力 | 冻结 warmup REST，λ=5，训练 256 步 |
| coev | 攻击器、REST、baseline、λ | 测量对抗训练是否改善布线模型 | 从同 seed warmup REST 和对应 fixed 攻击器继续 256 步 |

配置是 degree30、seeds201/202/203、batch32、每中心 K8。任务数为 `3 个 warmup + 6×3 个 fixed + 10×3 个 coev = 51`。十个共同训练分支包括 ERM、Random、ES、六种学习攻击器和 population PPO。

## 8. 研究版 REINFORCE：从其他候选的均值判断动作好坏

代码入口：[单步采样分支](/remote-home/Guilin/DRO/Codex/rl_research_20260915/policies.py:338)、[_reinforce_update](/remote-home/Guilin/DRO/Codex/rl_research_20260915/policies.py:218)。

### 8.1 一轮训练的完整流程

1. 冻结本轮的 REST 和 λ。
2. 先评价原中心，得到 \(F_0=L_\theta^g(X)\)。
3. 用同一旧策略，为每个中心独立生成 7 个完整位移动作。
4. 合法化后一次批量评价 7 个候选，得到 \(F_1,\ldots,F_7\)。
5. 对每个候选计算其他 6 个候选的平均 F，作为条件 baseline。
6. 重新计算原始高斯动作的联合 log probability，用 REINFORCE 做一次梯度更新。
7. 在这一批已经评分的原中心和 7 个候选中返回 F 最大者。

对 \(J=K-1\) 个提案：

\[
A_j=F_j-\frac1{J-1}\sum_{l\ne j}F_l,
\qquad
\mathcal L_{\rm RF}=-\frac1{BJ}\sum_{b,j}
\operatorname{stopgrad}(A_{bj})\log p_\omega(a_{bj}\mid X_b,\lambda).
\]

仅一个提案时，代码退回使用 \(F_0\) 作 baseline；正式 K8 不走这个特例。

### 8.2 为什么用其他候选作 baseline

不同中心的线长难度不同。直接用原始大线长作为奖励，可能主要反映“这个 net 本来就长”。同一中心的其他独立提案提供了对照，使更新更集中于相对较好的位移。

给定 X、λ 和当前策略，其他候选与第 j 个动作条件独立，因此该 baseline 不依赖第 j 个动作本身。这是降低方差的基线，不是新增的目标函数，也不需要额外真实评分。

### 8.3 它和 RL-only 的关系

核心估计器相同，但研究版显式输入 λ，并采用共同 warmup → 固定攻击训练 → 共同训练的分阶段流程。RL-only 则直接从随机初始化进行长一些的在线交替训练。不能把两个同名 REINFORCE 的差异全部归因于策略网络。

## 9. 普通 PPO：用同一批反馈做多轮受限制的策略更新

代码入口：[_ppo_update](/remote-home/Guilin/DRO/Codex/rl_research_20260915/policies.py:188)、[普通 PPO 调用](/remote-home/Guilin/DRO/Codex/rl_research_20260915/policies.py:356)。

### 9.1 候选怎样生成

搜索部分与研究版 REINFORCE 相同：评价原中心，独立生成 7 个完整候选，合法化并取得真实 F。区别主要在于**如何用这批动作和奖励更新策略**。

保存采样时的动作和旧 log probability，并定义候选相对原中心的增益：

\[
g_j=F_j-F_0.
\]

价值网络预测当前状态下这个增益的期望。采集完成后、PPO 多轮更新开始前，固定优势：

\[
\widehat A_j=g_j-V_{\nu,\rm old}(s).
\]

减去 \(F_0\) 只是同一中心下的基线变换，未改变攻击的大小顺序；它不是减去最优线长或几何下界。

### 9.2 4 个 epoch 内发生什么

整组 pin 被视为一个联合动作。新的联合概率与行为策略概率的比值为：

\[
r_j(\omega)=\exp\left(
\sum_{i=1}^{n}\log p_\omega(a_{j,i}\mid s)
-\sum_{i=1}^{n}\log p_{\rm old}(a_{j,i}\mid s)
\right).
\]

其中每个 pin 的 log probability 已对两个坐标分量求和。最大化裁剪目标：

\[
\mathcal J_{\rm PPO}=
\operatorname{mean}_j\left[
\min\{r_j\widehat A_j,
\operatorname{clip}(r_j,1-.2,1+.2)\widehat A_j\}
\right].
\]

实现最小化它的负值，同时训练 value 去拟合 \(g_j\)。默认 4 个 epoch、学习率 `3e-4`、梯度范数裁剪 1，熵系数为 0，不做 advantage 标准化。为了数值稳定，log ratio 在指数运算前另外限幅到 `[-30,30]`。

4 轮之间动作、旧概率、真实奖励和优势都保持固定；value 虽继续训练，不会重新计算本批 actor 优势。**4 个 epoch 是复用反馈进行优化，不是额外生成 4 批候选。**

### 9.3 搜索时和训练时的区别

~~~text
训练：旧策略采样 → 真实评分 → 保存动作/旧概率/奖励
    → 固定优势 → 同一批数据做 4 轮 PPO → 返回本批最佳候选

只搜索：策略采样 → 真实评分 → 返回最佳候选
~~~

普通 PPO 的更新目标仍以单次提案的期望增益为基础。即使部署时选 7 个候选中最好的一项，它也未直接把“整组最大值”写进优势。

## 10. Best-of-K PPO：直接奖励“改变最终最佳候选”的动作

代码入口：[replacement_advantages](/remote-home/Guilin/DRO/Codex/rl_research_20260915/policies.py:64)、[bestof_ppo 调用](/remote-home/Guilin/DRO/Codex/rl_research_20260915/policies.py:357)。

### 10.1 要解决的训练与使用差异

部署时，7 个候选中只要有一个足够强，就可能提高最终攻击分数。普通 PPO 倾向于改善单次采样平均质量；best-of-K 则针对：

\[
J_K(\omega)=\mathbb E_{a_1,\ldots,a_{K-1}\sim p_\omega}
\left[\max\{F_0,F_1,\ldots,F_{K-1}\}\right].
\]

它依然是从原中心生成多个独立候选，不是在一条轨迹上逐步移动。

### 10.2 替换基线怎样计算

先计算本组的最好分数：

\[
M=\max\{F_0,F_1,\ldots,F_{K-1}\}.
\]

对提案 j，暂时把它从集合中删掉，计算剩余候选的最大分数：

\[
b_{-j}^{\max}=\max_{l\ne j}F_l,
\qquad A_j^{\max}=M-b_{-j}^{\max}.
\]

删除的只是提案 j，原中心始终参与 baseline。这个量的直观含义是：**如果没有这个候选，最终攻击结果会损失多少？**

例如，一次示意搜索得到：

| 项目 | 原中心 | 提案 1 | 提案 2 | 提案 3 |
|---|---:|---:|---:|---:|
| F | 4.00 | 4.10 | 4.70 | 4.30 |
| 最大值替换优势 | 不训练 | 0 | 0.40 | 0 |

只有提案 2 严格提高最终最大值，它相对次优的贡献是 `.40`。若两个提案并列第一，删除任意一个后最大值不变，两者的本次优势都为零；若原中心最好，所有提案的优势都为零。

### 10.3 实际流程

1. 旧策略独立产生 7 个完整位移动作。
2. 评价原中心与 7 个合法候选，形成真实 F 表。
3. 对每个提案计算 \(A_j^{\max}\)。
4. 固定这些优势，用整组 pin 联合概率比做 4 轮 PPO 裁剪更新。
5. value 仍拟合 \(F_j-F_0\)，但 actor 使用显式传入的替换优势，不再用 value 值减一次 baseline。
6. 返回本组真实 F 最大的坐标。

在旧策略处，\(\mathbb E[\sum_j A_j^{\max}\nabla\log p_\omega(a_j)]\) 给出期望最大值的评分函数梯度；代码对候选取平均，只相差固定的正比例系数。经过多轮 PPO clipping 后，这是一个局部代理更新，不能解释成每轮都精确优化新策略下的期望最大值。

该方法的代价是训练信号较稀疏：大量非赢家候选没有 actor 优势。是否因此学得更好，需要看同预算真实搜索评价，而不能只看其目标更贴近择优。

## 11. Sequential PPO：根据已经得到的评分继续搜索

代码入口：[序贯搜索循环](/remote-home/Guilin/DRO/Codex/rl_research_20260915/policies.py:308)。

### 11.1 从“一批独立提案”变为“一条搜索轨迹”

K8 的分配是：**原中心评价 1 次，随后移动并评价 7 次**。下一步动作会看到当前坐标位移、当前分数增益、历史最好分数增益，以及剩余搜索进度。

可将状态写成：

\[
s_t=(X,d_t,\lambda,t/7,F_t-F_0,M_t-F_0),
\qquad M_t=\max_{0\le l\le t}F_l.
\]

初始 \(d_0=0\)、\(F_0=M_0=L_\theta^g(X)\)。

### 11.2 每一步怎样移动

对 \(t=0,\ldots,6\)：

1. 策略根据 \(s_t\) 产生高斯增量 \(a_t\)。
2. 将该增量逐坐标限制到 `±.04`。
3. 加到当前位移上，并将相对原中心的累计位移限制到 `±.08`。
4. 合法化后得到 \(Z_{t+1}\)。
5. REST 重新生成 greedy 树，计算：

\[
F_{t+1}=L_\theta^g(Z_{t+1})-\lambda c_{\rm index}(X,Z_{t+1}).
\]

6. 更新历史最好分数 \(M_{t+1}=\max(M_t,F_{t+1})\)。
7. 保存状态、原始动作、旧 log probability 和奖励。

运输代价始终相对原中心 X 计算，不能替换成相邻两步之间的距离。下一步从**本步新位置**继续，即使本步分数变差，也不会自动退回历史最好位置；历史最好分数只作为状态和奖励的一部分。

### 11.3 为什么奖励采用“历史最佳增量”

每一步奖励为：

\[
r_t=M_{t+1}-M_t\ge0.
\]

如果这一动作没有刷新最好分数，立即奖励为零。取折扣因子 1 时：

\[
\sum_{t=0}^{6}r_t=M_7-F_0.
\]

所以累计奖励正好等于最终 best-of-trajectory 的攻击增益。实现使用反向累加的 Monte Carlo return：

\[
G_t=\sum_{u=t}^{6}r_u,
\qquad \widehat A_t=G_t-V_{\nu,\rm old}(s_t).
\]

当前代码没有在这里使用 GAE 或 TD bootstrap。一个暂时没有即时改善的动作，若为后续发现更好的位置提供了条件，仍可通过后续 return 得到学习信号。

### 11.4 完整伪代码

~~~text
评价 X，令 current = X，best_score = F(X,X)
冻结本条轨迹的攻击行为策略、REST 和 lambda
重复 7 次：
    读取原坐标、当前位移、价格、进度和两个分数增益
    采样一组 pin 位移增量
    限制单步增量和相对 X 的总位移，再合法化
    对新坐标做真实评分
    reward = max(best_score, new_score) - best_score
    保存本步状态、原始动作、旧概率、reward
    更新 current 和 best_score
从所有状态的奖励反向求和，得到各步 return
整组 pin 使用联合动作概率比，做 4 轮 PPO
从 X 及 7 个已评分位置中返回真实 F 最大者
~~~

**策略是在整条轨迹结束后更新，而不是每移动一步就更新一次参数。** 只搜索时同样保留反馈驱动的 7 步移动，但不更新参数。

## 12. Pin-agent MAPPO：序贯搜索中的合作多智能体更新

代码入口：[与序贯方法共享的轨迹](/remote-home/Guilin/DRO/Codex/rl_research_20260915/policies.py:308)、[per-pin PPO ratio](/remote-home/Guilin/DRO/Codex/rl_research_20260915/policies.py:188)。

### 12.1 “多智能体”是谁

每个 pin 对应一个攻击 agent，每个 agent 输出该 pin 的二维移动增量。所有 pin 合作，目标都是提高整张 net 的攻击分数；它们共享参数和团队奖励。

REST 是被攻击的对手，不是这组 MAPPO agent 中的一个。当前实现也不是把整个 REST 布线策略改成 MAPPO。

### 12.2 它的搜索轨迹与 Sequential PPO 相同

本项目实际采用以下流程：

1. 评价原中心。
2. 每一步由所有 pin agent 同时输出动作，形成一个整网候选。
3. 合法化并评价整网 F。
4. 用历史最佳增量给所有 agent 同一个团队奖励。
5. 共执行 7 步，构造相同的 Monte Carlo return。
6. 用集中式状态价值网络形成团队优势，更新共享 pin 策略。
7. 按整网真实 F 返回历史最佳候选。

因此这里不是“每次只动一个 pin”，也不是“每个 pin 单独接受一次真实评分”。一次环境步仍只评价一张完整 net。

### 12.3 与 Sequential PPO 的关键差别

Sequential PPO 对所有 pin 的概率先相乘，再对联合比值做一次 clipping；MAPPO 对每个 pin 分别计算：

\[
r_{t,i}=\exp\{\log p_\omega(a_{t,i}\mid s_t)-\log p_{\rm old}(a_{t,i}\mid s_t)\},
\]

并采用：

\[
\mathcal J_{\rm MAPPO}=\operatorname{mean}_{t,i}
\min\{r_{t,i}\widehat A_t,
\operatorname{clip}(r_{t,i},1-.2,1+.2)\widehat A_t\}.
\]

每个 pin 的比值包含其两个坐标分量；同一时刻的 \(\widehat A_t\) 广播给所有 pin。不同 pin 没有单独的差分奖励，也没有逐 pin 的反事实 baseline。

这会改变高维联合动作下的更新限制，但不会自动解决团队信用分配问题。某个 pin 的移动究竟贡献多少，仍主要靠共享奖励和策略梯度间接学习。

### 12.4 该怎样做机制比较

- MAPPO 对 Sequential PPO：网络输入、7 步轨迹、奖励、真实评分预算一致，主要区别是 per-pin 与 joint ratio/clipping。
- MAPPO 对普通单步 PPO：同时改变了搜索轨迹和概率比结构，结果差异不能全部归因于“多智能体”。

策略本身可读取全体 pin 的 pooling 摘要，价值网络也聚合全体 pin。准确描述应是“共享参数、可用全局上下文、团队奖励、逐 pin PPO 更新的合作攻击器”，不宜把它写成只观察局部信息的部分可观测系统。

## 13. MADDPG bandit：先拟合动作价值，再通过 Q 学习位移

代码入口：[_push_replay 与 _ddpg_update](/remote-home/Guilin/DRO/Codex/rl_research_20260915/policies.py:236)、[候选与回放标签](/remote-home/Guilin/DRO/Codex/rl_research_20260915/policies.py:352)。

### 13.1 实际实现的算法范围

代码名为 `maddpg_bandit`。它用共享 pin actor 输出连续动作，通过集中式 Q 对整个联合动作求梯度，是合作攻击队伍的确定性策略梯度简化版本。

它只有一次决策就终止，没有多步环境转移，也不是原始 MADDPG 中逐个更新独立 actor、冻结其他 actor 的完整实现。当前 actor 参数由所有 pin 共享，Q 梯度会通过整组 pin 的动作一起回传。

### 13.2 如何收集训练数据

搜索阶段仍然保留随机探索：

1. 评价原中心，得到 \(F_0\)。
2. 计算连续动作均值 \(\mu_\omega(X,\lambda)\)。
3. 在均值上叠加高斯探索噪声，独立生成 7 个完整动作。
4. 合法化并计算每个候选的真实 F。
5. 将 `(X, 执行后的位移 Z-X, lambda, F-F0)` 加入 replay。

Q 的动作输入是**合法化之后实际执行的位移**，不是原始高斯 latent action；这与 PPO 用原始动作计算概率比的用途不同。

默认 replay 容量为 8192，每次随机取至多 128 条，执行 1 次 Q 更新和 1 次 actor 更新。DDPG 更新不使用采样动作的 log probability，也没有通过该损失学习探索标准差；在这一实现中，探索噪声尺度保持其初始化设定。

### 13.3 Q 网络拟合什么

因为一步即终止，目标直接等于真实增益：

\[
y=F(X,Z)-F(X,X),
\qquad
\mathcal L_Q=\frac12\operatorname{mean}
\left[Q_\nu(X,Z-X,\lambda)-y\right]^2.
\]

这里没有 \(\gamma Q(s',a')\) 项。实现虽然保存 target actor / target Q，并做系数 `.005` 的 Polyak 更新，但它们不参与终止 bandit 的 bootstrap target。

### 13.4 actor 怎样通过 Q 更新

Q 拟合一步后，暂时冻结其参数，对策略的均值动作计算：

\[
\delta_\omega=
\operatorname{clip}_{[.1,.9]}(X+\mu_\omega(X,\lambda))-X,
\qquad
\mathcal L_\mu=-\operatorname{mean}Q_\nu(X,\delta_\omega,\lambda).
\]

梯度经过 Q 的动作输入回传到策略。均值由 `epsilon*tanh` 限制，actor 更新中另处理坐标窗口；真实采样时的重复点回退不通过可微方式展开。因此这一步优化的是学到的 Q 近似，最终仍要靠真实评分验证候选。

~~~text
带噪 actor 生成候选 → 合法化 → REST 真实评分
    → 存 replay → Q 拟合真实增益
    → 固定 Q 参数，沿 Q 的动作梯度更新 actor
    → 从本批已真实评分的候选中选最佳项
~~~

最终选择没有改成按 Q 最大值选坐标，也没有把 Q 预测值当作已确认的攻击效果。

### 13.5 固定对手和移动对手怎样处理 replay

- 固定阶段：REST 与 λ 不变，可以跨更新保留 replay；旧奖励仍属于同一个评分环境。
- 共同训练：每轮 REST 和 λ 都可能改变，代码在每次搜索前清空 replay，保留网络和优化器状态。

后一种情况下，MADDPG bandit 不享有跨外层更新复用旧奖励的优势。清空原因是旧线长与旧价格下的标签不能当作当前环境的真值。对应调用见 [runner.py](/remote-home/Guilin/DRO/Codex/rl_research_20260915/runner.py:201)。

## 14. Population PPO：在当前和历史 REST 对手间训练

代码入口：[初始化与继承 PPO](/remote-home/Guilin/DRO/Codex/rl_research_20260915/runner.py:82)、[对手采样和历史保存](/remote-home/Guilin/DRO/Codex/rl_research_20260915/runner.py:197)。

### 14.1 这是一种共同训练策略

`population_ppo` 内部实例化的攻击器方法就是 `ppo`，从同 seed 的固定阶段 PPO 检查点开始。它没有新建另一种候选生成网络，也没有单独的 population 固定攻击训练阶段。

它改变的是本轮攻击器的评分对象：

\[
\mathcal P_t=\{\text{当前 REST}\}\cup\{\text{最近至多 3 个历史 REST 快照}\}.
\]

初始历史池为空；每 64 次共同训练更新后保存一次 REST 快照，只保留最近 3 个。

### 14.2 一轮完整流程

1. 从当前 REST 和历史池中均匀随机选择一个对手。本轮整批中心共用这个被选中的对手。
2. 用普通 PPO 攻击策略，围绕 X 独立产生 7 个提案。
3. 被抽中的 REST 评价原中心及提案，用当前 λ 计算 F。
4. 依据这个对手的真实反馈做 4 轮 PPO 更新。
5. 选择对这个对手 F 最大的 \(Z^*\)。
6. **当前正在训练的 REST** 在 \(Z^*\) 上采样树并更新，即使评分者是旧快照。
7. 根据选中几何的成本更新 λ。
8. 到达 64 步间隔时，将更新后的当前 REST 加入快照池。

~~~mermaid
flowchart LR
    P[当前 REST 与历史快照池] --> S[均匀抽取一个评分对手]
    X[原中心 X] --> A[普通 PPO 生成 7 个提案]
    S --> F[对原中心与提案计算真实 F]
    A --> F
    F --> U[更新攻击器]
    F --> Z[选择该对手最难的 Z*]
    Z --> R[当前 REST 在 Z* 上采样并学习]
    R --> H[每 64 步保存快照]
    H --> P
~~~

### 14.3 它试图解决什么

只攻击不断变化的当前 REST，可能让攻击器仅适应短期弱点；保留历史对手可以让训练持续接触不同阶段的困难模式。这个机制可理解为历史对手课程。

但代码没有给每个候选都评价全部历史模型，也没有对不同模型的分数求平均后再择优。实际顺序是“先抽一个模型，再找它的困难候选”。这与“找到对整个模型混合平均最难的候选”不是同一目标：

\[
\mathbb E_{h\sim\mathcal P}\left[\max_Z F_h(X,Z)\right]
\quad\text{通常不同于}\quad
\max_Z\mathbb E_{h\sim\mathcal P}[F_h(X,Z)].
\]

此外，最终更新的是当前 REST，输入却可能由旧模型的评分决定，所以本分支不能直接解释为当前 REST 的精确 WDRO 内层。实现也没有 payoff matrix、meta-solver 或 Nash 求解过程，不能写成完整 PSRO。

## 15. 选出来的对抗样本怎样进入 WDRO / REST 外层

### 15.1 共同训练的一般顺序

对研究版普通对手分支，每轮流程可写为：

~~~text
输入当前 REST theta、攻击器 omega、价格 lambda、中心 batch X

1. 固定本轮评分用的 REST 和 lambda
2. 攻击器收集候选或一条轨迹，REST 给出真实评分
3. 用保存的数据更新攻击器及其 value / Q
4. 从本轮已评分候选中选择 Z*
5. 当前 REST 在 Z* 上重新采样一棵树
6. 计算 sampled 树的真实成本，更新 REST 和 REST baseline
7. 用本轮选中样本的平均运输代价更新 lambda
8. 保存训练状态，进入下一轮
~~~

第 3、4 步都使用更新前已经采集的数据：攻击器参数更新后，不会在同一轮免费重新生成候选再选一次。研究版 `search(train=False)` 则不更新策略、不改变 replay，只执行当前方法的搜索流程。

v3.1 的 `rl_joint4` 在线更新时机不同：先做本轮 REST 更新和价格更新，每 4 轮再单独采集新中心训练攻击器，详见第 4 节。population 的评分对手例外见第 14 节。

### 15.2 REST 自己的强化学习更新

设 REST 在 \(Z^*\) 上采样树 \(Y\sim\pi_\theta(\cdot\mid Z^*)\)，真实训练成本为 \(C(Z^*,Y)\)。它最小化：

\[
\mathcal L_{\rm REST}=\operatorname{mean}
\left[
\operatorname{stopgrad}\{C(Z^*,Y)-V_{\rm rest}(Z^*)\}
\log\pi_\theta(Y\mid Z^*)
\right].
\]

由于这里是最小化成本，损失前的符号与攻击器最大化奖励时的负号不同。成本高于 baseline 的布线动作，其概率倾向于被降低。

- v3.1 的 C 为采样树相对于同一候选参考长度的 regret。
- Oracle-free 的 C 为采样树的几何下界归一化成本。
- RL-only / RL research 的 C 为采样树自身线长。

REST baseline 通过回归 sampled 成本学习。它不会替代真实成本，也不是候选最终择优的裁判。研究版实现见 [update_actor](/remote-home/Guilin/DRO/Codex/rl_research_20260915/runner.py:174)。

### 15.3 价格 λ 怎样更新

若本轮选中样本的平均运输代价是 \(\bar c\)，代码执行：

\[
\lambda_{t+1}=\max\{0,\lambda_t+\eta_\lambda(\bar c-\rho)\}.
\]

- 平均移动成本超过目标 ρ，就提高价格，使后续大移动更昂贵。
- 平均移动成本低于目标 ρ，就降低价格，让攻击器有机会探索更远的输入。
- λ 是外层维护的标量，不是攻击器直接输出的动作。

研究版固定攻击阶段保持 λ=5；共同训练从 λ=5 开始，\(\eta_\lambda=10\)、\(\rho=.04\)。RL-only 则从 λ=1 开始。

形式上的 WDRO 对偶目标含有：

\[
\lambda\rho+
\mathbb E_X\left[\sup_Z\{q_\theta(Z)-\lambda c(X,Z)\}\right].
\]

其中 \(\lambda\rho\) 对同一 X 的候选择优是常数，所以没有出现在攻击奖励 F 中；它的作用体现在 λ 更新中。实际代码以有限候选近似内层，而且攻击用 greedy REST、外层用 sampled REST，因此这里描述的是工程上的交替近似流程，不能由该公式直接推导出已经求得精确鞍点。

## 17. 候选预算、计算预算和测试流程

### 17.1 K8 到底包含什么

研究版 K8 包含原中心，因此：

- 单步方法：1 次原中心评分 + 7 次提案评分。
- 序贯方法：1 次原中心评分 + 7 次状态转移后的评分。
- 不合格提案回退到 X 时，其评分请求仍占预算；8 项不保证是 8 个不同坐标集合。
- PPO 的 4 轮优化不增加本轮真实候选数。
- 攻击器预训练、REST sampled 训练、验证与最终评价各自另有成本。

### 17.2 有效评分数相同，不代表运算时间相同

研究版 batch32、K8，每轮有效评分都是 \(32\times8=256\) 张 net。实际 greedy 推理固定 microbatch64，并对不足部分补齐：

| 搜索方式 | 一轮有效候选评分 | 一轮含 padding 的 greedy 前向行数 | 原因 |
|---|---:|---:|---|
| Random | 256 | 256 | 全部候选一次联合评分 |
| ES | 256 | 320 | 探测与最后提案分开评分 |
| 单步学习攻击器 | 256 | 320 | 原中心 32 补到 64；224 个提案补到 256 |
| Sequential PPO / MAPPO | 256 | 512 | 8 次顺序评分，每次 32 补到 64 |

此外，PPO / MAPPO 多轮反向、MADDPG 的 Q 学习、历史对手加载、序贯同步都需要时间。所以准确说法是“匹配有效真实评分数量”，并同时报告实际前向行数、训练开销和时间。

预算实现见 [REST scorer](/remote-home/Guilin/DRO/Codex/rl_research_20260915/runner.py:157)，已有细化说明见 [THEORY_REVIEW.md](/remote-home/Guilin/DRO/Codex/rl_research_20260915/docs/THEORY_REVIEW.md:444)。

### 17.3 固定模型测试怎样做

研究版在每个训练 seed 的固定 warmup REST 上：

1. 使用独立的 uniform、mix_gauss、edge_bias、grid_cluster 中心，每分布 128 个。
2. 分别设置 λ 为 1、5、10；其中 5 是训练价格，1 和 10 是训练价格外评价。
3. 学习攻击器使用 `train=False`，并与 Random、ES 在同一中心上对照。
4. 每中心预算保持 K8，统计最大真实 F 相对原中心的 gain、选中线长、运输成本与 no-move 等。

这里的 gain 越大，表明固定模型上的有限预算搜索越强。没有 REST 参数更新。

### 17.4 共同训练后的模型怎样测试

对每个 coev 分支的最后一个 REST：

1. 在四分布上分别评价 1024 个独立 net，统计 greedy 自身线长。
2. 每分布另用 128 个攻击中心，接受独立 Random32 和 ES32 搜索。
3. 独立攻击使用 λ=0，因此主要寻找局部大线长，而不是求解 ρ=.04 约束下的最坏分布。
4. 比较共同训练分支的独立表现，避免只用它自己的攻击器给自己评分。

自然测试包括四个分布，报告里的 `nominal_length` 不应误解为只包含 uniform 分布。具体代码见 [evaluate](/remote-home/Guilin/DRO/Codex/rl_research_20260915/runner.py:218)。

## 18. 阅读和使用这些方法时应保留的结论边界

### 18.1 原始线长奖励也会偏好几何上本来更长的输入

在 RL-only / research 中，没有最优解或几何下界作归一化。攻击器找到更长的 REST 树，可能同时包含“输入本身更难”和“REST 解得更差”两个因素。它验证的是自身动作线长压力下的搜索与训练，不能单凭 F 变大推断最优性误差变大。

### 18.2 学到了策略，不代表一定胜过简单搜索

当前 [研究分支独立验收](/remote-home/Guilin/DRO/Codex/rl_research_20260915/artifacts/review_20260919/REPORT.md)已经确认冻结探索实验完成，但方法效果需要分开读：

- 固定模型上，PPO、best-of-K、Sequential PPO、MAPPO 相对 REINFORCE 的相关汇总区间跨零；不能宣称改进已经成立。
- 该配置中的 MADDPG bandit 明显弱于 REINFORCE。
- Sequential PPO 在共同训练后的常规四分布平均线长上有改善证据，但独立 Random32 / ES32 下相对 Random 的优势未建立。
- 历史对手 PPO 没有建立相对普通 PPO 的稳定综合优势。

这些只是本次 degree30、三个训练 seed、短程训练的探索性结论，相关区间未做多重比较校正。本文主要解释流程，不据此选定通用最优算法。

### 18.3 有 λ 更新，不代表每步或全程都满足 ρ

λ 调整是一种预算跟踪机制，有限候选和有限训练下仍可能超出平均运输目标。已有研究验收保留了这种超额事实。因此，需要分别看位移合法性、真实成本记录、平均预算和独立测试，不能仅看到公式正确就称为严格 Wasserstein 鲁棒保证。

### 18.4 哪些方法真正在一次搜索中利用了反馈

容易混淆的地方可直接这样判断：

| 说法 | 对当前代码的准确解释 |
|---|---|
| “RL64 一步步搜了 64 次” | 实际是原中心加 63 个单步独立提案 |
| “普通 PPO 用 4 轮新反馈训练” | 实际是旧策略采集的一批反馈复用 4 个 epoch |
| “best-of-K 就是普通 PPO 后面取最大” | 所有方法都择优；best-of-K 特有的是最大值替换优势 |
| “Sequential PPO 总是从最佳点出发” | 它从当前点继续，另保存历史最佳分数和最终候选 |
| “MAPPO 每次只动一个 pin” | 每步所有 pin 同时行动，组成一个候选并共享奖励 |
| “MADDPG 用 Q 分数取代真实评分” | Q 用来训练动作策略；最终仍以真实 F 选候选 |
| “population 对每个候选平均所有历史模型分数” | 每轮先抽一个评分对手，本轮只用该对手评分 |
| “训练用 REINFORCE，所以攻击搜索也是 RL” | REST 学习算法和攻击候选生成方式需要分别查看 |

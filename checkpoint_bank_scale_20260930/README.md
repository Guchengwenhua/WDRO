# Original-loop checkpoint reference experiment

faithful_trainer.py is copied from wdro_precision_v2/wdro_rest_min/stage6/trainer.py. Scientific loop, original initialization, fresh optimizer, original RNG namespaces, original data generator and candidate generator, original 33-to4 shortlist, lambda/cost, policy loss, validation timing and best-checkpoint criterion remain. adapters.py changes only explicitly recorded bookkeeping/runtime and reference interface; it does not edit historical source. Reference providers re-evaluate each actual Z. Historical content digests are read as identifiers but no new content digests or inverse audits run. Exact reference cache is disabled (increases solve calls, not values). Seed identity hashes are retained to reproduce original random streams.

Protocol is frozen in protocol.json; pool paths/metadata/source epochs and validation-only provenance are in inputs.json. The earlier 200step/batch64 continued pilot is not this baseline. The new Geo arm starts from the original legacy actor and fresh critic/Adam. Historical formal Geo results are context only because runtime identity and caching differ. All three arms use this same loop and differ by reference provider and declared teacher update policy. Lagged warmup uses anchor+legacy0 (2 members); after50 it has anchor+two snapshots, then evicts oldest lagged slot every50. This differs from the rolling pilot's historical-top3 warmup. All teachers eval/frozen; no teacher gradients. Negative bank targets are retained; original nonnegative critic remains a known approximation limitation.

The explicit authorized correctness check check_reference_equivalence.py compares actual original search/outerloss expressions versus Geo reference adapter on CPU batch8/d10 with identical input/RNG, including f/reference/Z/loss/lambda and all actor/critic state tensors after one update. equivalence.json records a pass. This is not a proof of full2000-step trajectory equality and not an engineering test suite.

Launch with bash launch.sh. Session checkpoint-bank-scale uses socket artifacts/scale.sock. Queue waits once on rolling queue.lock, then runs9 jobs sequentially onGPU5 with10% memory cap andCPU1. No polling wait helper. Artifacts reside on the attached2TB-free drive via documented symlink. queue_status.json and per-run heartbeat.json show progression/observed throughput. Every100steps original atomic checkpoint includes actor/critic/optimizer/scheduler/RNG/cursor/lambda and added teacher-bank state; snapshots are atomic. Restart only after prior session exits using same command. Completed jobs skip; failed job stops queue and retains logs. Test group NPZ writes atomically and reuses completed groups after restart. No d30 expansion is scheduled.

For bank arms, inherited reference_cache_hits/request counters describe interface requests and must not be interpreted as real scalar cache hits. reference_accounting is authoritative for teacher inference/exact solve counts and time. Each refresh.jsonl identifies bank_used_ids versus bank_next_ids at the post-update transition. Geo baseline disables scalar caching, so exact calls and runtime may differ from historical cached Geo runs even with identical values.
